# 기능 소개와 목업을 함께 갱신하는 기준

README는 처음 방문한 사람이 제품의 목적·화면·현재 상태를 확인하는 입구다. 함께 고친다. 기능이나 화면을 바꿀 때 구현 파일만 수정하지 않고 기능표·목업·사용법에서 달라진 부분을 반영한다.

## 변경할 위치

| 파일 | 담당 |
|---|---|
| `docs/product/features.json` | 기능 이름, 현재 상태, 확인 범위, 남은 일, 연결 화면 |
| `docs/mockup/template.html` | 가상 자료로 조작하는 화면 목업 |
| `scripts/build-product-docs.mjs` | README 소개 영역·기능 문서·SVG 설계 이미지·목업 HTML 생성 |
| `docs/experience-records.md` | 목적, 사용 흐름, 기록과 공개 원칙 |
| `README.md` | 생성된 소개 영역과 기존 실행 안내 |

기능을 바꾸면 먼저 상태와 검증 근거를 확인한다. 구분해서 쓴다. 기존 앱·로컬 검토판·샘플·모의 검사·실계정 검사·설계를 하나의 ‘완료’로 합치지 않는다. 예정된 기능의 목업 버튼에는 실제 저장이나 전송이 일어나지 않는다는 설명을 남긴다.

화면 구성이 바뀌면 HTML 목업과 SVG 설계 이미지의 배치도 맞춘다. 글도 맞춘다. 버튼 이름은 사용자가 누른 뒤 생기는 일을 설명하고, 저장 위치·개인정보·공개 범위 안내는 화면에서 확인할 수 있게 둔다. README 이미지의 대체 텍스트와 연결 주소도 확인한다.

생성·검사는 저장소 루트에서 실행한다.

```sh
node scripts/build-product-docs.mjs
node scripts/build-product-docs.mjs --check
```

생성 후 데스크톱과 작은 화면에서 메뉴·입력·미리보기를 확인한다. 실제로 연다. GitHub에 올린 뒤 README 이미지와 공개 목업 주소가 열리는지 확인하며, 게시한 파일과 공개 페이지의 버전이 일치하는지도 대조한다. CI는 생성 문서의 일치 여부를 검사하며 시각 검토와 실계정 시험을 대신하지 않는다.

## 공개 예시의 범위

목업에는 가상 사업·가상 문장만 넣는다. 원본은 제외한다. 실제 학생 자료·계좌·연락처·원본 사본·내부 PC 경로·비공개 회고·인증값을 넣지 않는다. 이미지 가림이나 개인 자료의 공개는 별도 검토와 승인 범위에 따른다.

문서 갱신 기준은 이후 변경에도 적용한다. 예약 작업은 아니다. 이 규칙이 원본 자료의 추가 수집·대량 변환·외부 서비스 게시를 자동 허가하거나 일시정지한 장기 목표를 재개하는 것은 아니다. 사용자에게 보고할 때는 확인한 공개 목업 주소와 남은 기능을 함께 적는다.
