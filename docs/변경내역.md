### 옮기다 끊겨도 어긋나지 않는다 (10)

- 이동·복사를 시작하기 «전에» 무엇을 할지 연결한 폴더의 `PKOS-transfer.json` 에 적는다: 원본과 지문, 만든 사본, 고쳐 쓸 문서의 원문. 목록을 저장한 뒤에는 「원본 마저 지우기」 단계로 표시를 바꾸고, 다 끝나면 지운다.
- 다시 연결할 때(또는 다음 옮기기 전에) 그 기록이 남아 있으면 마무리한다. 목록 저장 전에 끊겼으면 사본을 걷고 문서를 원문으로 되돌린다. 목록 저장 뒤에 끊겼으면 아무 기록도 안 쓰는 원본만 지운다. 어느 쪽이든 «지문이 같을 때만» 손댄다. 밖에서 바뀐 파일은 그대로 두고 알린다.
- 옮기는 도중 실패했을 때도 같은 기록으로 사본을 걷는다. 전에는 「대상 폴더에 사본이 남아 있을 수 있습니다」 로 끝났다.
- 이 파일은 색인·설정처럼 기록으로 세지 않는다. 이름 변경 쪽의 복구 저널(PC 연결 프로그램)과 같은 생각이다.

### 문서 안 그림을 더 읽는다 (11)

- 워드 머리글·바닥글의 그림(로고·도장)을 본문 그림 뒤에 잇는다.
- 엑셀 시트에 붙은 그림판(drawing)의 그림, 한글(HWPX) BinData 그림(`content.hpf` 목록으로 찾는다), 오픈문서(odt·odp·ods)의 Pictures 그림을 읽는다.
- 그림 «찾기» 와 «싣기» 를 갈랐다. 형식마다 어디에 그림이 있는지만 모으고, 크기 한도·형식 확인·표시는 한 곳에서 한다. 한도(한 장 4MiB · 문서당 8MiB · 48장)는 그대로.

### 파워포인트 발표자 메모 (12 가운데 되는 것)

- 슬라이드 아래 「메모: …」 로 잇는다. 본문 검색도 이 줄을 본다. 쪽 번호만 있는 메모는 뺀다.

### 고른 기록 묶음 (13)

- 엮어내기 창에 「묶음으로 저장」 을 두었다. 고른 기록을 책 제목 칸의 이름으로 «검색 묶음» 에 남긴다. 묶음을 열면 그 기록들만 보이고 「✕ 필터 지우기」 로 돌아온다. 저장한 검색 조건은 원래 있던 「현재 조건 저장」 이 그 일이었다.

## 2026-09-16 · 탐색기에서 지우고 만든 폴더·태그가 화면에 그대로 따라온다

폴더나 태그를 지우고 만들어도 화면에 계속 남는다는 이야기를 받았다. 네 가지가 겹쳐 있었다.

- 위쪽 태그 칩이 «폴더에서 사라진 기록» 의 태그까지 세고 있었다. 목록과 왼쪽 태그는 빼고 세는데 칩만 달랐다. 같은 자를 쓰게 했다.
- 탐색기에서 만든 빈 폴더는 어디에도 서지 않았다. 왼쪽 나무를 기록에서만 세웠기 때문이다. 이제 폴더를 훑을 때 본 폴더를 그대로 세운다.
- 한 번 저장 위치로 고른 폴더는 밖에서 지워도 남았다. 고른 자리는 기기에 적어 두는데 그 자리가 아직 있는지 아무도 보지 않았다. 훑은 뒤 없는 자리는 목록에서 빼고, 지금 쓰던 자리였으면 놓는다.
- 글은 그대로이고 폴더만 생기거나 사라진 경우에는 화면을 다시 그리지 않았다. 그래서 새 폴더가 다음 변화가 올 때까지 안 보였다. 폴더 구성이 바뀌면 왼쪽을 다시 그린다.

실시간 반영은 원래 있던 길을 그대로 쓴다. 앱이 화면에 보이는 동안 2초마다 연결한 폴더를 훑는다. 이번에 폴더 구성도 그 훑기에 함께 실린다.

### 확인한 것

- `docs/점검도구/폴더태그반영.mjs` 10개 통과. 브라우저 안 폴더(OPFS)를 붙여 앱 «밖에서» 파일과 폴더를 만들고 지웠다. 고치기 전에는 태그 칩·빈 폴더·저장 위치 세 가지가 실패했다.
- `docs/점검도구/홈화면.mjs` 24경우, `docs/점검도구/고정주소최신판.mjs` 13개 통과.
- 사용자의 실제 기록 폴더로는 시험하지 않았다.

### 알아 둘 것

- 앱이 화면에 보이지 않으면(다른 탭·창 최소화) 훑지 않는다. 다시 보는 순간 맞춘다.
- `.git` `.obsidian` `.trash` `.pkos-conflicts` 폴더는 전처럼 건너뛴다.
- 왼쪽 나무는 네 칸 깊이까지만 세운다(SIDE_DEPTH). 더 깊은 폴더는 「실제 폴더 구조」 창에서 본다.
- 구글 드라이브만 연결한 방식은 이번 훑기 대상이 아니다. 폴더 연결(PC 연결 앱·브라우저 폴더 열기)에서 동작한다.


## 2026-09-15 · 앱 주소 고정 · 새 판은 같은 주소에서 바로 열린다

배포를 확인할 때마다 `?deploy=커밋`을 붙인 주소를 건네 왔다. 사용자에게는 배포 주소가 자꾸 바뀌는 것으로 보였다. 꼬리를 붙인 이유는 캐시였다. 서비스 워커가 브라우저 캐시를 그대로 써서, GitHub Pages의 `max-age=600` 동안 같은 주소가 옛 판을 열었다.

- `sw.js`가 앱 파일을 열 때마다 서버에 확인한다(`cache: "no-cache"`, 바뀐 것이 없으면 304). 인터넷이 끊기면 전처럼 마지막으로 받은 판을 연다.
- 배포할 때 `version.json`을 만든다(커밋, 시각, 커밋 메시지, 주소). 앱은 열 때와 다시 볼 때(5분 간격) 확인한다. 펴 둔 동안 새 판이 올라오면 편집 칸 위에 «새 판이 올라왔습니다 · 새로고침»을 띄운다. PC 연결 앱과 로컬 미리보기에는 이 파일이 없어 한 번 묻고 멈춘다.
- 설정 → 고급 맨 위에 앱 주소, 주소 복사, 지금 연 판을 보인다. PC 연결 앱에서는 PC 연결 앱 주소를 보인다.
- `?deploy=` 꼬리로 들어오면 주소창에서 지운다. 즐겨찾기와 앱 설치가 고정 주소를 잡는다.
- 로컬 미리보기 설정(저장소 밖 `.claude/launch.json`)을 파이썬 서버 두 벌(8777, 8791)에서 `띄우기.ps1` 하나(8123)로 줄였다.

- `docs/점검도구/홈화면.mjs` 24경우 통과. 가로 넘침과 실행 오류가 없다. 375px 폭에서 설정 → 고급의 주소 줄이 화면을 넘지 않는다.

## 2026-09-12 (2) · 첨부를 옮기면 그 파일을 쓰는 다른 기록의 링크도 따라간다 · PC 연결 프로그램 파이썬 경로

첨부 파일을 «이동» 할 때, 기록 자신뿐 아니라 같은 파일을 쓰는 다른 기록의 Markdown 도 고쳐 쓴다. 본문의 `![]()` 링크, 참조 정의 `[ref]: <...>`, HTML `src=`·`href=`, 머리말의 `file:`·`driveId:` 를 새 경로로 바꾼다. 코드 블록·인라인 코드·들여쓴 코드 안의 링크 예문은 건드리지 않는다. 퍼센트 부호화된 경로와 괄호가 든 파일 이름도 풀어서 맞춘다.

같은 파일을 쓰는 기록이 편집 중이거나 저장 대기 중이면 이동을 거부한다. 문서를 고쳐 쓰기 직전에 지문을 다시 대조해, 그 사이 밖에서 바뀐 문서는 덮어쓰지 않고 이동을 중단한다. 원본 파일과 밖에서 고친 문서는 그대로 남는다.

전체 보기의 Markdown 읽기도 같은 규칙으로 맞췄다. `~~~` 울타리 코드 블록, 괄호가 든 링크, 제목이 붙은 그림 링크를 읽는다.

구글 문서 사본 · 링크로 공유 · 웹 쪽으로 공유 · 영상 스트리밍 재생 · 드라이브 고르기 창. 드라이브 ID 가 없어서다. 사용자가 포기하기로 했다(9/11).
휴대폰(드라이브 API)은 PC 가 쓴 기록을 **읽기만** 한다 · 사진은 안 뜬다. `local:` ID 를 이름으로 되찾는 대응은 후속.

### 손댄 곳

`localSyncPending` · `localSaveIndex` · `localSaveSettings` · `localLoad` · `localTrashEntry` · `localRestoreEntry` · `localPurgeEntry` · `localImport` · `localPick` · `localBoot` · `localPermit` (5-9 절).
`syncPending` `saveIndex` `saveSettingsRemote` 첫 줄에서 폴더 쪽으로 갈라진다. `if (connected)` 로만 보던 자리 13곳은 `connected || localOn`.
`slim()` 에 `localDir` 를 더했다. `driveLink()` 가 `local:` 을 안다. 점검용 `window.pkosLocal` 손잡이.

## 기록 유형과 태그 통합

작성 화면에서 유형과 태그가 따로 움직여 선택 상태와 미리보기가 어긋났다. 분류를 태그 하나로 합쳤다.

### 변경

- 연수, 아이디어, 자료를 일반 태그와 같은 목록에 저장한다. 여러 개를 함께 선택하고 모두 해제할 수 있다.
- 새 기록은 태그 미선택으로 시작한다. 설정의 태그 탭에서 사용 중인 태그를 확인한다.
- 이전 기록의 유형은 해당 이름의 태그로 읽는다. 중복을 제거하고, 다시 저장할 때 Markdown에는 tags만 쓴다. 이전 type 필드는 읽기 호환용으로만 처리한다.
- 목록, 미리보기, 검색과 지식맵은 같은 태그를 사용한다. 파일 이름에는 첫 번째 태그를 반영하고 전체 태그는 기록의 메타데이터에 저장한다.
- 기존 원본 파일을 일괄 개명하거나 덮어쓰지 않는다. 기록을 수정해 저장할 때 새 규칙을 적용한다.

### 검증

격리된 임시 폴더에서 브라우저로 여러 태그 선택, 태그 삭제, 파일명 반영, 저장 후 재접속을 검사했다. 이전 유형에서 옮겨 온 태그도 삭제 후 재접속했을 때 되살아나지 않았다. 카드와 모바일 배치 검사도 통과했다.

PC 연결 검사는 저장 규칙에 따라 이름이 바뀐 첨부를 허용하고, 파일 내용 BRIDGE-ORIGINAL까지 확인하도록 보강했다.

### 고정 추천 목록 제거

사용자가 왼쪽 태그 목록과 작성 화면의 연수, 아이디어, 자료 목록이 다른 점을 지적했다. 고정 추천 목록을 제거하고 두 화면이 저장된 기록에서 같은 태그 목록을 읽게 고쳤다. 새 태그는 기록을 저장하면 두 목록에 반영된다. 태그가 없는 새 기록은 미선택을 유지한다.

브라우저 검사에서 양쪽 태그 이름과 순서가 일치하고, 태그를 여러 개 선택해 저장한 뒤 다시 연결해도 유지되는 것을 확인했다.

### 설정에서 태그 이름 변경

설정의 태그 탭에 태그별 입력칸과 이름 변경 버튼을 추가했다. 버튼을 누르면 해당 태그를 사용하는 기록, 작성 중 태그, 검색 필터를 함께 바꾼다. 같은 이름은 하나로 합치고 빈 이름은 거부한다. 왼쪽 태그의 이름 변경 메뉴도 이 설정 화면으로 연결한다.

PC 연결 프로그램을 켜지 않아도 태그를 변경할 수 있다. 연결이 끊겼다면 변경을 브라우저에 보관하고 재연결 때 파일에 반영한다. 실제 폴더 이름을 태그 변경에 맞춰 강제로 바꾸지는 않는다.

브라우저 검사에서 설정 편집, 작성 중 태그 반영, 중복 병합, 빈 이름 차단, 재접속 보존, 연결 해제 중 변경 후 재연결 보존을 확인했다.

## DOC·XLS·HWP와 ZIP 자동 압축 해제

2026-09-13 작업 기록.

PC 앱: http://127.0.0.1:8788/?localBridge=1

DOC는 Word의 별도 자동화 인스턴스에서 읽기 전용 사본을 열어 PDF로 표시한다. 매크로 자동 실행과 열 때 링크 갱신을 비활성화한다. XLS는 시트를 선택하고 100행씩 넘겨 읽는다. 가로 스크롤로 넓은 표를 본다. 수식은 저장된 계산 결과이며 다시 계산하지 않는다. HWP 5는 본문 구역을 순서대로 읽는다. XLS와 HWP는 프로그램 실행 없이 로컬 라이브러리로 처리한다.

세 형식 모두 본문 검색에 연결했다. 검색과 미리보기가 동시에 요청돼도 변환 순서를 기다린다. 원본의 SHA-256을 함께 확인해 같은 크기·수정 시각으로 바뀐 파일도 이전 미리보기를 사용하지 않는다.

PC 앱 또는 폴더에 새 ZIP을 넣거나 기록에 첨부해 저장하면 ZIP 옆에 같은 이름의 폴더를 만들고 압축을 푼다. 기존 폴더가 있으면 (2), (3)을 붙인다. ZIP 원본은 유지한다. 임시 폴더에 전부 쓴 뒤 새 폴더를 표시하며, 실패하면 임시 결과를 정리한다. 해제된 파일은 기존 폴더 읽기 흐름에서 기록으로 가져온다. ZIP 속 ZIP은 다시 풀지 않는다.

ZIP은 원본 128MB, 압축 해제 합계 512MB, 항목 2,000개까지 처리한다. 상위 폴더 경로, 절대 경로, 링크·특수 파일, Windows 예약 이름, 중복 항목과 암호 ZIP은 거부한다. 자동 해제는 PC 연결 앱에서 제공한다. 브라우저 폴더 연결과 Google Drive API 전용 모드에는 이번 자동 해제를 추가하지 않았다. G:의 Google Drive 동기화 폴더는 PC 연결에서 사용할 수 있다.

제한: HWP 표 안의 글은 읽지만 표 배치·그림·수식·글꼴을 재현하지 않는다. 암호·배포용 HWP와 HWP 3은 지원하지 않는다. XLS 차트·그림·셀 서식은 재현하지 않으며 전체 셀 50만 개를 넘으면 안내한다. 본문·결과 32MB 한도를 적용한다. DOC에는 Word가 필요하다. 공개 웹사이트만으로 PC 프로그램을 실행할 수 없다.

검증: 단위·저장·복구 검사 60개 통과. 격리된 PC 앱 화면 검사 16개 통과. DOC 실제 렌더링, XLS 두 번째 시트와 120행, HWP 예제 본문, 세 형식 검색, ZIP 드롭·압축 해제·원본 보관·해제 파일 검색, 재접속 후 검색을 확인했다. DOC·XLS·HWP·ZIP 원본 바이트가 같았다. 사용자 기록과 블로그 파일은 시험 대상으로 쓰지 않았다.

검증 명령: python -m unittest discover -s local-service -p "test_*.py" 및 python local-service/check_legacy_ui.py. 시험 파일 재생성은 local-service/create_legacy_fixtures.py로 실행한다. 시험용 xlwt는 local-service/runtime/test-vendor에 설치하며, HWP 예제는 설치된 한글 2024의 Present1.hwp를 임시 폴더로 복사한다. 예제 원본은 저장소에 넣지 않는다.

변경 파일: index.html, sw.js, local-service/server.py, presentation_preview.py, preview_word.vbs, legacy_document.py, extract_zip.py. PC 전용 라이브러리 olefile 0.47과 xlrd 2.0.2는 local-service/vendor에 라이선스와 함께 보관한다. PC 실행 폴더와 문서 사본은 공개 배포에서 제외한다.

구현 근거: [Word 읽기 전용 열기](https://learn.microsoft.com/en-us/office/vba/api/word.documents.open), [Word PDF 내보내기](https://learn.microsoft.com/en-us/office/vba/api/word.document.exportasfixedformat), [한컴 HWP 본문 구조](https://tech.hancom.com/python-hwp-parsing-2/), [xlrd API](https://xlrd.readthedocs.io/en/latest/api.html).

### 자동 파일명 줄이기

새 기록 폴더의 기본 이름을 제목으로 변경했다. 새 기록 파일과 자동 이름을 쓰는 첨부는 저장 폴더 이름과 확장자만 사용한다. 기존 설정은 한 번 새 규칙으로 전환하며 기존 저장 파일명과 외부 원본 이름은 유지한다. 동일 이름 처리는 기존 중복 번호 규칙을 사용한다. 앱 스크립트 문법과 폴더 이름 선택 및 원본 이름 유지 조건 5개를 확인했다.

### 첨부 파일 카드와 자동 읽기 알림

편집창과 읽기 화면의 첨부 파일을 이름·형식·열기 메뉴가 있는 카드로 변경했다. PC 연결에서는 기본 앱, 파일 탐색기, 이름 변경, 사본 다운로드를 제공한다. 기본 앱 실행은 문서·미디어 확장자로 한정한다. 자동 폴더 확인의 quiet 옵션을 지키도록 수정했고, Markdown 내부 drive 주석은 글로 표시하지 않는다. 격리 브라우저 검사 4개와 기본 앱 호출 모의 검사, 회귀 검사 60개를 통과했다.

기존 파일 날짜 제거와 기록 통합은 미실행 상태다. 자동 승인 검토가 재귀 이름 변경과 태그·본문·인덱스 수정이 결합된 정리를 거절했다. 개인 작업 폴더에 파일명만 바꾸는 65개 확인안을 남겼다. 실행 전 범위 확인이 필요하다.

### 수정 저장 위치와 사진 로딩

하단 sticky 저장 줄이 본문 미리보기와 겹쳐 정적 배치로 변경했다. 이미지 요청을 파일별로 합치고, 공유 Blob 주소는 화면에서 더 이상 쓰지 않을 때 해제한다. 첨부 메타데이터를 처음 읽을 때 불필요하게 캐시를 지우지 않는다. 읽기 실패는 총 3회 시도하며 이후 클릭 재시도를 안내한다. 사진 캐시·재시도·문법 검사와 격리 브라우저 6개 검사(실제 편집 저장 포함)를 통과했다. 원본 사진 파일을 수정하거나 이동하지 않았다. 저장 경로에 실물이 없는 오래된 사진은 이번 수정만으로 복구되지 않는다.

### 기록 목록 접기 UI

목록을 접을 때 생기던 세로 띠를 없애고 편집창 위에 가로 목록 펼치기 버튼을 배치했다. 접힌 목록의 그리드 칸은 제거하고 접기 버튼에 글자와 접근성 속성을 추가했다. 접기 안내와 지연된 보조 사용 안내를 제거했다. 오류 및 저장 결과 알림은 유지한다. 격리 브라우저 검사 13개를 통과했다. 1920·1280픽셀 접기와 펼치기, 390픽셀에서 펼치기 버튼 접근을 확인했다.

### 도구 모음 겹침과 목록 숫자

스크롤 도구 모음의 투명 배경을 불투명 패널로 변경했다. 휴지통·미정리함 등 상태 메뉴 선택 시 이전 검색·유형·태그·고정 필터를 초기화한다. 유형별 숫자와 전체 숫자는 현재 상태 목록을 기준으로 집계하고, 휴지통 숫자는 목록에서 제외하는 누락 원본 기록을 동일하게 제외한다. 격리 브라우저 검사 16개를 통과했다. 개인 기록과 원본 파일은 변경하지 않았다.

### 목록과 편집·미디어 간소화

기록 목록은 제목을 누르면 아래로 펼쳐지는 방식으로 변경했다. 휴지통 우클릭과 모바일 점 메뉴에서 전체 복원·삭제를 제공하며 삭제는 확인 후 실행한다. 상단의 할 일·목록·번호 목록·인용·코드·역할별 인용·코드 삽입 중복 버튼을 제거했다. 기존 기록의 해당 블록과 Markdown 파서는 유지한다. Markdown 제목·목록·인용·코드 울타리는 저장 시 블록으로 변환한다.

사진 편집의 로컬 파일 읽기를 고치고 사진 클릭으로 모자이크·펜·색상·되돌리기를 제공한다. 새 사진 파일은 입력된 기록 제목과 확장자를 쓰고 중복 번호만 추가한다. 편집 중인 첨부를 별도 기록으로 다시 가져오지 않도록 인식한다. 기존 개인 원본은 일괄 변경하지 않는다.

녹음은 파일만 첨부하며 본문 자동 저장과 전사 안내문 삽입을 제거했다. 새 녹음은 브라우저 디코딩 후 길이가 명시된 WAV로 변환한다. 디코딩을 지원하지 않으면 원본 녹음을 보존한다. 기존 음성도 로컬 및 로그인된 Drive에서 네이티브 재생과 길이 보정을 사용한다. WAV는 압축 녹음보다 용량이 크다.

사진 픽셀 변경, 파일 이름, 음성 첨부, 실제 MediaRecorder 길이 변환, Markdown 저장, 휴지통 복원 및 390·768·1024·1280·1920픽셀을 포함한 새 UI 검사 21개와 기존 UI 검사 16개를 통과했다. 실제 휴대폰 하드웨어·모바일 마이크 권한·실제 Google 로그인 업로드는 이번 격리 검사에 포함하지 않았다.

### 지식 탐색과 웹 수집

앱을 처음 열면 기록창이 열린다. PKOS 제목을 누르면 최근 기록, 연결이 많은 기록, 자주 등장한 단어와 미니 지도가 보인다. 작성 중인 초안은 홈으로 이동하기 전에 임시 보관한다.

관계망과 태그 집계는 휴지통, 로컬 부재, 드라이브 부재 및 연결 폴더 밖 기록을 제외한다. 보관 데이터 자체를 삭제하지 않는다. 본문과 제목, 추출된 첨부 텍스트에서 공통 단어가 2개 이상인 기록을 자동 연결한다. 자동 연결은 수동 관계에 저장하지 않는다. 선을 누르면 근거 단어를 읽는다. 단어 화면은 사용 횟수에 따라 크기를 정하고, 2개 이상 기록에서 함께 등장한 단어를 연결한다. 한국어 형태소 분석이나 의미 임베딩은 적용하지 않았다. 문서별 상위 40단어, 기록 연결 500개, 단어 40개 및 단어 연결 160개로 표시 범위를 제한한다. 80개를 넘는 기록에 쓰인 단어는 기록 간 자동 연결 계산에서 제외한다.

할 일 탐색 메뉴와 삽입 메뉴를 제거했다. 기존 문서의 체크 목록은 보존한다. 캡처 선택창은 이미지 파일, 카메라, 화면 캡처 버튼만 남겼고, 붙여넣기 단축키는 유지한다. 캡처 후 자르기를 기본으로 연다. 웹 브라우저의 화면 공유 대상 선택은 생략하지 않는다. 자동 민감정보 탐지나 자동 모자이크는 구현하지 않았다. 사진 편집에서 직접 영역을 표시한다.

웹 클리퍼는 제목, 선택한 글, 출처 URL을 검토한 뒤 현재 초안에 추가한다. 클리퍼의 '선택한 글 가져오기' 링크를 PC 북마크바에 끌어 놓고, 웹페이지에서 글을 선택한 뒤 실행한다. URL과 텍스트는 PKOS 주소의 fragment로 전달하며 자동 저장하지 않는다. 브라우저 정책에 따라 북마크 실행이 제한될 수 있다. 모바일에서는 글과 주소를 직접 붙여 넣는다. 사이트 바로가기는 이 브라우저의 로컬 저장소에 남으며 기기 간 동기화하지 않는다. http/https 이외 주소는 거부한다.

검증: 임시 기록 폴더와 별도 Edge 프로필에서 기존 편집·미디어 21개와 지식 탐색 18개 점검 통과. 관계망은 390/768/1280 폭, 홈은 390 폭에서도 가로 넘침이 없었다. 실물 휴대폰 카메라와 Google OAuth는 이번에 시험하지 않았다. 공개 배포는 이전 전송 승인 차단이 해제되기 전까지 보류한다.

### 전체 자료 화면과 메뉴 축소

PKOS 제목을 누르면 현재 자료 전체가 이미지와 제목 카드로 열린다. 검색과 최근순, 자동 연결 수 정렬을 제공한다. 시작 화면은 기록창으로 유지한다. 웹 클리퍼와 사이트 바로가기는 왼쪽 폴더 목록 아래에 둔다.

미정리함 탐색 항목, 나중에 정리 체크박스, 유형 만들기 버튼을 화면에서 제거했다. 기존 파일과 기록의 저장 값은 보존했다. 긴 도움말을 전체 자료, 새 기록, 지식맵, 웹 클리퍼, 설정 버튼으로 대체하고 사용자에게 보이는 관계 용어를 정리했다. 캡처와 설정의 부연 설명을 줄였으며 오류 및 저장 상태는 유지한다.

의견 버튼은 파란 배경과 선명한 말풍선 SVG, 의견 보내기 글자로 표시한다. 연락처 입력과 자동 화면 진단 전송을 제거했다. 본문, 유형, 사용자가 첨부한 이미지를 전송하는 기존 기능은 유지한다. 이번 시험에서 실제 의견 전송은 실행하지 않았다.

임시 데이터와 독립 Edge 프로필에서 편집 21개, 지식 탐색 및 화면 23개 점검을 통과했다. 390픽셀 모바일 자료 화면을 이미지로 확인했다. 공개 GitHub 전송은 승인 차단 상태이므로 로컬 수정과 커밋까지만 완료했다.

### 설정과 파일 처리 재점검

로컬 연결 중에도 가져오기 탭이 Google 연결 여부만 검사해 비활성화되던 오류를 수정했다. 로컬 모드에는 폴더 다시 읽기와 파일 가져오기를 제공한다. 파일 가져오기는 현재 편집창의 파일 이름 확인 및 첨부 저장 경로를 사용한다. 가져오기 실패 후 버튼이 다시 활성화되도록 처리했다.

비어 있던 기록 유형 탭에 연수, 아이디어, 자료를 표시했다. 파일 이름 설정은 폴더 이름 또는 글 제목을 고르며 사진은 글 제목을 쓴다. 날짜 토큰은 새 저장 규칙에서 제거하고, 가져오는 문서의 YYYY-MM-DD 접두어는 이름 제안에서 뺀다. 사용자가 이름 확인창에서 수정할 수 있다. 기존 파일은 일괄 변경하지 않는다. 태그가 곧 폴더 문구는 태그별 폴더로, 기본 자리 괄호 표기는 폴더 이름만 보이도록 정리했다.

검증 결과: 파일 저장, ZIP 해제 및 원본 보존, 경로 검증, 이름 변경 복구, 문서 처리, 앱 재실행, 두 브라우저 동시 저장 등 60개 검사 통과. 기존 브라우저 저장 검사 3개는 삭제된 홈 빠른 입력창을 사용해서 실패했으며 현재 새 기록 버튼과 제목 입력칸으로 갱신한 뒤 통과했다. 화면 및 설정 35개 검사도 통과했다. 모양, 저장 위치, 가져오기, 기록 유형, 파일 이름, 의견 받기, 고급 탭을 열었고 로컬 가져오기와 이름 설정 저장 및 재열기를 시험했다.

실행 중인 PC 서비스는 02_구글 기록장을 사용하며 /api/status에서 ready=true를 확인했다. 실제 Google OAuth, 모바일 기기 촬영, Google Drive 동기화 완료 여부, 실제 Office/Hancom 프로그램 실행은 이번에 검증하지 않았다. 자동 정리는 선택한 저장 폴더와 파일명 규칙을 적용하는 범위이며 내용에 따른 자동 폴더 분류는 구현 범위에 포함하지 않는다. GitHub 공개 배포는 전송 승인 대기다.

### 모양 독립 설정과 폴더 다중 선택

색감에 섞여 있던 화면 배치와 글자 크기 규칙을 기본 배치로 분리했다. 글자 크기는 아주 작음, 작음, 보통, 크게, 아주 크게이며 글꼴은 고딕, 명조, 시스템, 굴림, 고정폭에서 선택한다. 글꼴은 기기에 설치된 글꼴과 대체 글꼴을 사용한다. 선택값은 색감을 바꿔도 유지하며 저장하지 않고 닫으면 원래 설정으로 돌아간다. 다크 모드 색감 카드와 캡처 버튼의 흰 배경을 수정하고 경계선 대비를 높였다.

기록 유형 설정은 새 기록의 기본 유형을 선택한다. 작성 중인 초안의 유형은 바꾸지 않는다. 상단 폴더 이름은 자료 목록을 열며 저장 위치 변경은 아래 설정에서 한다. 폴더 목록은 Ctrl/Cmd 토글 선택과 Shift 연속 선택을 지원하고 선택 폴더의 자료를 함께 표시한다. 다중 선택 중 저장 위치는 바꾸지 않는다. 일괄 이동과 삭제 기능은 이번 변경에 포함하지 않는다.

사이트 추가로 버튼 이름을 줄이고 새 사이트에는 제목을 받는다. 기존 YouTube 주소 표시는 YouTube로 바꾸고 제목 수정 버튼을 추가했다. 자동 웹페이지 제목 조회는 하지 않는다. 의견 받기 탭에서 흐릿한 이모지를 제거했다.

임시 폴더와 별도 브라우저 프로필에서 화면 점검 45개 통과. 색감 변경 전후 실제 제목 글자 크기 및 글꼴 일치, 설정 저장/취소, 새 기록 기본 유형, Ctrl 2개 폴더 선택, Shift 3개 폴더 선택, 다크 캡처 색상을 확인했다. 다크 모드 모바일 설정 화면을 이미지로 확인했다.

목록 접기와 펼치기는 상단의 동일 버튼에서 전환한다. 사이트 추가를 탐색 메뉴 디자인으로 맞추고 자식 없는 폴더 앞 빈 펼침 영역과 선택 강조선을 제거했다. 저장 방식은 왼쪽 아래에 브라우저, 로컬 폴더, 구글 드라이브로 표시하고 상단 중복 표시를 숨겼다. 글 아래의 저장 대상은 저장 폴더로 구분하며 연결 해제 안내는 유지한다.

### 필기 지우개와 인식 입력 보정

기본 펜을 굵게로 바꾸고 지우개 크기를 작게, 보통, 크게로 분리했다. 전체 지우기는 필기판 위에 배치했다. 획을 유지한다. 펜 압력의 최소 굵기를 높이고 화면 경계에서 획이 끊기는 처리를 수정했다.

인식용 복사본은 흑백으로 보정하고 빈 여백을 줄인다. 원본은 유지한다. 인식 중 필기를 변경하면 이전 결과를 표시하지 않는다. 브라우저 검사에서 지우개 크기별 삭제 범위, 되돌리기와 전체 지우기를 확인했다. 실제 OCR 엔진의 인쇄체 인식 검사는 통과했으며 손글씨 정확도 향상은 수치로 측정하지 않았다.

### ZIP 첨부 해제와 사진 도구 선택

파일 올리기에서 ZIP 내부 파일을 풀어 첨부로 넣는다. 사진도 표시한다. 기존 ZIP에는 압축 풀어 넣기 버튼을 제공하며 로컬 폴더에 직접 넣은 ZIP도 브라우저에서 해제할 수 있다. 파일 이름은 UTF-8과 한국어 CP949를 읽고 압축 내용의 CRC와 크기를 검사한다. 암호 ZIP과 지원하지 않는 압축 방식은 실패를 표시하고 원본을 유지한다. 현재 파일별 16MB, 전체 48MB 해제 한도를 적용한다. 기록에 넣을 때는 내부 파일을 첨부 목록으로 펼치며 로컬 폴더에 직접 넣을 때는 내부 하위 폴더를 유지한다.

사진 도구는 선택한 버튼을 진하게 표시하고 펜을 선택하면 모자이크 입자 설정을 숨긴다. 펜 색상은 펜에서만 보인다. 펜 커서도 실제 선 굵기에 맞췄다. 브라우저에서 한글 ZIP 해제 내용, 파일 올리기 후 첨부 삽입, 잘못된 경로 거부와 사진 편집을 확인했다.

### 기록별 폴더와 선택 태그

폴더 구성은 기록마다 폴더 생성으로 통일했다. 태그별 폴더 선택은 제거했다. 새 기록과 외부 첨부의 태그 기본값은 빈 목록이며 폴더 이름으로 태그를 자동 생성하지 않는다. 기존 기록의 태그와 실제 저장 위치는 유지한다.

### 현재 동작

화면 공유 영상과 마이크 음성을 함께 녹화한다. 내 얼굴을 켜면 웹캠 영상을 오른쪽 아래에 합성한다. 화면 소리는 선택 사항이며 공유 대상과 브라우저가 제공하는 경우에만 포함된다. 출력 화면은 1280×720이다.

마이크 선택과 3초 시험 녹음을 제공한다. 입력 크기 막대와 실제 음성 트랙 이름을 표시하고, 시험 녹음 재생으로 목소리를 확인한다. 화면 음성이 없으면 마이크 트랙을 녹화기에 직접 넣는다. 화면 음성이 있으면 마이크와 혼합한다. 실시간 전사는 브라우저가 별도로 선택한 음성 입력을 사용할 수 있다.

일시 정지, 계속 녹화, 종료를 지원한다. 종료 후 기록에 넣기를 누르면 영상 파일과 시간 표시가 붙은 전사문이 들어간다. 원래 작성 중인 기록을 중간에 저장했어도 그 기록을 찾아 첨부한다. 현재 작성칸에 들어간 영상은 기록 저장 버튼으로 저장을 마친다. 로컬 폴더 또는 드라이브 연결 시 기존 기록 동기화 경로를 사용한다. 영상 저장 버튼은 파일을 직접 내려받는다.

한국어 전사는 브라우저 음성 인식 기능을 사용한다. 인식된 문장을 수정할 수 있다. 브라우저 제공 업체의 음성 처리 서버를 사용할 수 있으며, 지원되지 않거나 연결이 끊기면 전사가 빠질 수 있다. 전사 오류가 영상 녹화를 멈추지는 않는다. 녹화 종료 후 음성을 다시 전사하는 별도 AI 엔진은 아직 구현하지 않았다.

녹화 조각은 1초 간격으로 이 브라우저의 IndexedDB에 저장한다. 창을 닫았다가 강의 녹화를 다시 열면 저장된 이전 녹화를 복구할 수 있다. 마지막 미저장 조각은 복구되지 않을 수 있다. 브라우저 데이터 삭제나 저장 장치 고장까지 보장하는 백업은 아니다. 임시 저장 공간이 부족해지면 녹화를 종료하고 내려받기 경로를 제공한다.

### 검증 범위

Edge에서 합성 화면, 합성 웹캠, 오실레이터 음성으로 실제 MediaRecorder를 실행했다. 합성 화면의 색상, 얼굴 위치, 시간 표시 전사, 일시 정지, 트랙 종료, 저장 조각 복구, 영상 첨부와 녹음된 음성의 디코딩을 확인했다. 전사 엔진은 시험 대역을 사용했으므로 실제 한국어 인식 정확도를 측정한 결과는 아니다.

실제 카메라와 마이크, 수업 한 회 분량의 녹화, 브라우저가 배경으로 이동한 상황, 시스템 음성 포함, 연결된 로컬 폴더와 드라이브의 대용량 업로드는 실제 장비로 추가 확인해야 한다.

### 문서 이미지 미리보기 보강

DOCX 본문과 PPTX 슬라이드에 포함된 PNG·JPEG·GIF·WebP 이미지를 텍스트 아래에 표시한다. 이미지가 여러 장이면 이전·다음 버튼으로 넘긴다. 편집창과 전체 보기에서 사용할 수 있다.

문서 내부 이미지 연결만 읽는다. 외부 이미지 주소와 지원하지 않는 형식은 읽지 않으며 본문은 계속 표시한다. 이미지 한 장 4MiB, 문서당 이미지 데이터 8MiB, 표시 항목 48개로 제한한다. 한도를 넘긴 이미지는 생략 안내를 표시한다. 본문 검색에서는 이미지 데이터를 읽지 않는다.

원본의 글꼴·배치·도형 효과와 구형 문서 형식은 아직 재현하지 못한다. DOCX 머리글·바닥글 이미지, XLSX·HWPX·OpenDocument 내부 이미지는 이번 범위에 포함하지 않았다.

### 이름 변경 강제 종료 복구

이름 변경 전에 문서와 색인의 변경 전 내용, 변경 후 내용, 경로와 대상 식별값을 비공개 실행 폴더의 복구 기록에 저장한다. 복구 기록을 디스크에 기록한 뒤 실제 파일을 바꾼다. 재시작하거나 다음 쓰기를 처리하기 전에 미완료 작업을 확인한다.

색인까지 저장된 작업은 유지한다. 색인 저장 전에 중단된 작업은 문서와 경로를 원래 상태로 되돌린다. 복구 도중 다시 종료돼도 다음 실행에서 이어서 복구한다. 문서·색인·경로가 외부에서 바뀌었거나 복구 기록이 손상됐으면 원본과 복구 기록을 남기고 추가 쓰기를 차단한다.

복구 기록은 local-service/runtime/rename-<폴더식별값>.json에 저장하며 웹으로 제공하거나 Git에 넣지 않는다. 복구 충돌 시 해당 파일을 지우지 않는다. 인수 담당자가 현재 문서와 기록된 변경 전후 내용을 대조해 외부 수정본을 별도로 보존한 후 경로·내용을 정리해야 한다. 충돌이 해소되면 다음 폴더 점검에서 복구를 다시 시도한다.

별도 프로세스를 저장 단계마다 실제 종료하는 검사, 복구 재중단, 외부 수정 보존과 HTTP 쓰기 차단, 손상된 복구 기록 검사를 추가했다. 기존 저장·동시 쓰기 검사와 합쳐 34개가 통과했다. 태그·폴더 이름 화면 검사 7개도 통과했다. 개인 원본은 시험에 사용하지 않았다.

이 결과는 프로세스 강제 종료 복구를 검증한다. 실제 전원 차단과 저장장치 고장, 이동·복사 전체의 다중 파일 복구까지 입증한 것은 아니다.

### 첨부 파일 단독 이동의 문서 연결 유지

첨부 파일만 옮길 때 앱 색인만 바뀌고 저장된 Markdown 링크는 옛 경로에 남는 문제를 수정했다. 해당 첨부를 사용하는 기록의 링크와 첨부 메타데이터를 새 경로로 갱신한 뒤 색인을 저장한다. 원본 문서를 다시 생성하지 않고 링크 부분만 바꾼다.

상대 경로, 한글·괄호 파일명, 이름 충돌, 설명이 붙은 이미지 링크, 참조형 링크, HTML src·href를 처리한다. 주석과 코드 예시는 유지한다. 이미지 링크의 설명이 파일명에 섞이는 가져오기 오류도 수정했고 물결표 코드 울타리를 인식하도록 했다.

첨부를 사용하는 기록이 편집 중이거나 문서가 외부에서 수정됐으면 이동을 중단한다. 문서를 쓰기 직전에도 내용을 대조한다. 실패하면 원본 첨부를 지우지 않고 완성된 대상 사본을 남긴다. 일부 연결 문서가 이미 수정된 경우에는 남아 있는 대상 사본을 가리킬 수 있다.

연결 이동 검사 12개가 브라우저 저장소와 실제 PC 임시 폴더에서 각각 통과했다. 공유 첨부 문서 두 개, 원본 바이트, 줄바꿈·BOM·주석·코드 보존, 외부 수정 보존과 재연결 경로를 확인했다. 기존 이동·복사 검사 16개도 통과했다.

모든 문서 형식 안의 링크를 일괄 수정하는 기능이나 이동 작업 전체의 강제 종료 복구를 검증한 것은 아니다. 개인 기록과 블로그 원본은 시험에 사용하지 않았다.

### 폴더 이름 변경 시 첨부 파일명 보존

폴더 이름을 바꾸면 하위 첨부의 표시 이름도 폴더 이름으로 바뀌던 오류를 수정했다. 새 첨부 경로에서 실제 파일명을 가져오도록 했다. 파일명을 직접 바꾸는 동작은 기존처럼 새 파일명을 반영한다.

PDF·PPTX·PNG·HWP의 파일명과 확장자, 원본 이름, 바이트를 함께 대조했다. 저장·복구 회귀 검사 35개가 통과했다. 실제 PC 임시 폴더에서 태그와 폴더를 연속 변경한 뒤 앱을 다시 열었으며, 첨부 파일명과 DOCX 본문 미리보기를 포함한 화면 검사 9개가 통과했다.

시험은 새로 만든 파일로 수행했다. 사용자 원본 문서는 변경하지 않았다. 이 결과는 모든 문서 형식의 미리보기나 폴더 밖 문서의 모든 링크 보존까지 입증한 것은 아니다.

### 첨부 이동 때 다른 기록의 링크 갱신 · PC 연결 프로그램 파이썬 경로

첨부 파일을 이동하면 같은 파일을 쓰는 다른 기록의 Markdown 링크·참조 정의·HTML 속성·머리말도 새 경로로 바꾼다. 코드 블록과 인라인 코드 안의 예문은 바꾸지 않는다. 같은 파일을 쓰는 기록이 편집 중이면 이동을 거부하고, 고쳐 쓰기 직전에 지문을 대조해 밖에서 바뀐 문서는 덮어쓰지 않는다.

첨부이동연결.mjs 12개가 통과했다. 격리한 브라우저 폴더만 썼고 사용자 기록은 옮기지 않았다.

local-service/start.ps1이 파이썬을 C:\Python314 한 곳에서만 찾아 이 PC에서 «Python runtime unavailable» 상태가 되던 것을 고쳤다. 알려진 설치 폴더와 PATH를 차례로 본다. 고친 뒤 서버를 띄워 ready 상태를 확인했다.

Windows 시작프로그램 등록은 자동 승인 검토에서 거절돼 실행하지 못했다. 이전 인수인계서의 «시작프로그램에 등록했다»는 이 PC의 시작프로그램 폴더·Run 키·예약 작업에서 확인되지 않았다. 사용자가 직접 등록해야 한다.

### PPT 본문 검색 연결

PC 연결 앱의 검색창에서 구형 PPT 슬라이드 안의 문장으로 기록을 찾는다. 미리보기를 먼저 열지 않아도 검색이 PDF 사본 변환을 요청한다. 같은 원본의 완료된 변환은 미리보기와 검색에서 함께 사용한다.

검색어를 바꾸거나 지우면 이전 검색 결과를 적용하지 않는다. 이미 시작한 PowerPoint 변환은 자체 종료 절차를 따르며 사용자의 Office 작업을 강제로 종료하지 않는다. 검색 결과는 PDF의 텍스트를 읽어 판정하고 원본 PPT와 기록 문서를 다시 쓰지 않는다.

새로 만든 PPT로 화면 검사 12개가 통과했다. 미리보기를 열기 전 본문 검색, 두 번째 슬라이드 검색, 없는 문장의 결과 제외, 앱 재실행 후 검색, 검색어 지우기와 기존 슬라이드 표시를 확인했다. 저장·복구 검사 48개도 통과했다. 시험 원본의 바이트가 같았다.

Windows PC 연결과 설치된 PowerPoint가 필요하다. 첫 변환에는 시간이 걸린다. 변환 실패는 첨부 검색의 읽지 못한 파일 수로 표시한다. 이미지 속 글자 인식, 발표자 메모 검색, DOC·XLS·HWP 미리보기는 이번에 추가하지 않았다. PPS도 같은 경로로 처리하지만 실제 파일 검증은 PPT로 수행했다. 블로그 원본은 변경하지 않았다.

변경 파일: index.html, sw.js, docs/점검도구/구형PPT미리보기.mjs. 검증 실행: python local-service/check_presentation_ui.py.

### 실행과 배포

공개 앱은 https://legoschool.github.io/pkos/ 이다. PC 연결 앱은 http://127.0.0.1:8788/?localBridge=1 이다. GitHub Pages에서는 Python 프로그램을 실행하지 않으므로 PC 전용 폴더 이름 변경과 백그라운드 연결은 PC 앱에서 사용한다.

저장소의 main 브랜치에 반영하면 GitHub Actions가 공개 사이트 파일만 배포한다. 개인 기록 목록과 실행 로그는 포함하지 않는다.

### 이번 기능

외부 문서 파일을 넣을 때 저장 이름을 입력한다. 폴더 구조에서 파일명을 바꾸면 실제 파일명과 첨부 경로를 갱신한다. 확장자는 유지한다.

태그와 하위 폴더 이름을 우클릭 메뉴로 바꾼다. 태그와 같은 이름의 최상위 하위 폴더가 있으면 함께 바꾼다. 이름 충돌은 거부한다. 실패하면 변경을 되돌린다.

목록과 지식맵에서 기록을 폴더로 끌어 복사·이동을 고른다. 기록과 첨부를 함께 처리하며 파일 검증과 색인 저장 후 원본을 정리한다. 공유 중이거나 작업 도중 바뀐 원본은 남긴다.

문서·미디어 미리보기, 녹음 처리, 로컬 저장의 기존 보완 사항을 함께 반영했다. 이번 배포 검증을 전체 환경의 모든 기능 검증으로 표현하지 않는다.

### 보존 원칙

사용자의 기존 기록은 시험 데이터로 사용하지 않는다. 블로그 기록의 추가 정리는 사용자에게 남겼다. 사용자가 직접 선택한 작업 외에는 원본 파일을 일괄 변경하지 않는다.

### 점검과 남은 범위

파일 이름 변경과 태그·폴더 변경은 임시 실제 폴더 및 Edge 화면으로 점검한다. 이동·복사는 분리된 브라우저 저장소에서 실제 마우스 드래그와 파일 바이트를 확인한다. 렌더링 엔진과 인증 등 외부 서비스 전체를 새로 검증한 것은 아니다.

PC 자동 실행은 local-service/start.ps1과 startup.vbs를 사용한다. PC가 꺼지거나 절전 중이면 처리가 멈춘다. 설치 환경의 폴더 경로를 확인한다.

주요 파일: index.html, view.html, document-preview.js, pdf-reader.js, local-bridge.js, local-service/server.py, local-service/rename_ops.py.

이번 커밋은 현재 파일과 배포본을 정리한다. 과거 Git 이력 재작성은 별도의 범위 확인이 필요하다.

## 구형 PPT 미리보기 인수인계

PC 연결 앱에서 구형 PPT를 첨부하고 전체 보기 또는 편집창의 «슬라이드 미리보기 만들기»를 누른다. 설치된 PowerPoint로 PDF 사본을 만들고 기존 PDF 뷰어로 표시한다. PowerPoint를 사용 중이면 변환을 시작하지 않으며 다른 작업의 프레젠테이션을 닫지 않는다.

원본은 비공개 실행 폴더에 복사한 뒤 읽기 전용 사본으로 열고 매크로 비활성화를 요청한다. PDF는 원본과 별도 경로에 저장한다. 기존 출력은 덮어쓰지 않으며 원본 변경을 감지하면 캐시를 사용하지 않는다. 복사본의 변환 전후 해시도 확인한다. 공개 웹사이트만으로는 PC의 PowerPoint를 실행할 수 없다.

작업은 별도 프로세스로 실행한다. 앱 화면은 상태를 확인하다가 PDF가 준비되면 표시한다. 변환 중 뷰어를 닫아도 변환기는 작업을 마치고 자신이 연 프레젠테이션을 닫는다. 3분 안에 끝나지 않으면 앱은 다시 확인하라는 안내를 표시한다. 사용자 Office 작업을 강제로 종료하지 않는다.

같은 파일의 완료된 미리보기를 재사용한다. 한 번에 변환 하나를 실행하고 현재 서버 실행에서 최대 12개 작업을 보관한다. 원본 크기는 128MB까지 받는다. 재시작 전 실행에서 남은 캐시 폴더를 일괄 정리하는 기능은 아직 없다. 실행 중 작업을 잘못 지우지 않도록 이 부분은 후속 관리 과제로 남긴다.

새로 만든 두 장짜리 구형 PPT로 화면 검사 7개가 통과했다. 텍스트·파란 도형 렌더링, 다음·이전 슬라이드, 캐시 재사용과 원본 바이트 일치를 확인했다. 저장·복구·미리보기 작업 관리 검사 48개도 통과했다. 기존 Word 프로세스는 종료하지 않았다. 개인 원본은 시험에 사용하지 않았다.

변환기는 PPS·PPTX·ODP도 받을 수 있도록 구성했지만 이번 실제 파일 검증은 PPT에 한정했다. DOC·XLS·HWP의 본문 미리보기, PPT 본문을 앱 전체 검색에 넣는 작업, 모든 슬라이드 효과의 재현은 완료하지 않았다.

주요 파일: local-service/presentation_preview.py, local-service/preview_powerpoint.ps1, local-service/server.py, index.html. 검사는 local-service/check_presentation_ui.py와 docs/점검도구/구형PPT미리보기.mjs로 실행한다. 시험 파일 생성기는 local-service/create_presentation_fixture.ps1이다.

변환 방식은 Microsoft의 [Presentations.Open 문서](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentations.open), [SaveAs 문서](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.presentation.saveas), [AutomationSecurity 문서](https://learn.microsoft.com/en-us/office/vba/api/powerpoint.application.automationsecurity)를 확인했다.

## 2026-09-12 · 폴더 연결 수정 인수인계 (docs/인수인계_폴더연결_2026-09-12.md 였던 것)

## 폴더 연결 수정 인수인계

폴더 이름을 바꿀 때 다른 폴더의 Markdown 문서가 옛 경로를 계속 가리키던 오류를 수정했다. 파일명 변경이 다른 경로의 같은 이름까지 바꾸던 오류도 수정했다. 문서 위치에서 실제 대상 경로를 계산하고 변경 대상에 해당하는 링크만 바꾼다.

일반 링크와 이미지 링크, 참조형 링크, HTML src·href, 머리말의 local 첨부 식별값을 처리한다. 폴더 안에서 경로 관계가 그대로인 링크는 원문을 유지한다. 외부 웹 주소와 코드·주석 속 예시, 들여쓴 코드는 바꾸지 않는다. 인코딩된 파일명과 쿼리·문서 내 위치를 유지한다.

색인에 등록된 로컬 Markdown을 점검한다. 폴더 밖 문서의 변경도 기존 이름 변경 복구 기록에 포함한다. 강제 종료 후 되돌릴 때 문서 링크도 복구한다. 기록되지 않은 파일 형식 내부 링크나 모든 형식의 연결을 지원한다고 판정한 것은 아니다.

저장·복구 회귀 검사 42개, 실제 PC 임시 폴더 화면 검사 10개가 통과했다. 폴더를 연속 변경하고 재실행한 뒤 외부 문서 링크와 DOCX 미리보기를 확인했다. 변경 전 실패하던 두 회귀 사례가 수정 후 통과했다. 개인 원본은 시험에 사용하지 않았다.

주요 파일은 local-service/markdown_paths.py와 local-service/rename_ops.py다. 검사는 test_markdown_paths.py, test_rename.py, test_rename_recovery.py, check_rename_ui.py와 docs/점검도구/태그폴더이름.mjs에 있다.

### 발견하고 고친 문제

기록이 있는 홈에서 좁은 화면의 열 너비가 내용 길이에 끌려 늘어났다. 지식맵과 최근 기록이 오른쪽 밖으로 밀렸다. 반응형 열의 최소 너비를 0으로 설정하고 자식 영역도 줄어들게 고쳤다. 보통·큰 글자 24개 조합과 화면 이미지에서 수정 결과를 확인했다.

밝은 기본 화면의 보조 글자는 대비 4.48:1, 태그는 3.89:1이었다. 보조 글자색을 짙게 바꿔 각각 5.91:1과 5.13:1로 높였다. 공유 화면에도 같은 색을 적용했다. 검사한 요소의 최저 대비는 밝게 4.58:1, 어둡게 5.02:1이었다. 모든 화면 요소의 접근성을 전수 검증했다는 뜻은 아니다.

공유·대비 검사 도구는 localhost라는 글자가 든 창만 찾았다. 대상 주소의 출처와 일치하는 창을 찾도록 고쳤다. 설정 검사는 예전 탭 6개와 설명 40자를 기대했다. 현재 탭 7개와 유형 이름 입력칸을 검사하도록 바꿨다. 어두운 화면 검사도 설명 문구 대신 실제 ‘어둡게’ 단추를 선택하게 고쳤다.

## 폴더와 미리보기

설정의 저장 위치에서 PC 폴더를 고릅니다. Google Drive 데스크톱에 연결된 폴더를 고르면 앱을 닫아도 Drive가 파일을 동기화합니다. PC가 꺼져 있거나 절전 상태면 동기화가 멈춥니다. PKOS 기록 목록은 앱이 열려 있을 때 갱신됩니다.

앱은 2초마다 변경을 확인합니다. 파일 수와 Drive 다운로드 속도에 따라 반영 시간이 늘어납니다. 창으로 끌어 놓은 파일은 선택한 폴더의 받은 파일에 저장됩니다. 이름이 겹치면 번호를 붙입니다. 같은 작업에서 넣은 사진과 영상은 한 기록으로 묶습니다.

폴더에서 삭제한 기록은 목록에서 숨기고 파일이 돌아오면 다시 표시합니다. 앱과 폴더에서 같은 글을 수정한 경우 외부 원본을 .pkos-conflicts에 보관한 뒤 앱의 글을 저장합니다. 앱 관리 색인과 .git, .obsidian, .trash, .pkos-conflicts는 일반 자료로 가져오지 않습니다.

HTML은 별도 미리보기 안에서 실행됩니다. 상대 경로 이미지와 스타일 파일을 읽습니다. 외부 링크는 사이트가 삽입을 허용해야 표시됩니다. 차단된 사이트는 원본 열기를 누릅니다. 영상은 브라우저가 지원하는 형식이어야 재생됩니다.

점검: 미리보기동기화.mjs는 격리된 브라우저 시험 폴더에서 추가·수정·삭제·복원, 파일 205개, HTML, URL, 사진과 영상 슬라이드를 확인합니다. 실제 개인 폴더와 Google Drive 클라우드 동기화 완료 여부를 검증하는 시험은 아닙니다.

### 로컬 추가 검증

아직 배포하지 않은 document-preview.js가 DOCX, XLSX, PPTX, HWPX 문단·셀·슬라이드 텍스트와 ZIP 목록을 읽는다. 원본 레이아웃·그림 재현은 미완료다. 구형 HWP, DOC, XLS, PPT는 아직 읽지 못한다. 브라우저 안에서 압축을 읽으며 원본을 외부 변환 서비스에 전송하지 않는다.

문서미리보기.mjs로 DOCX 드롭 후 본문 표시, XLSX 셀 주소·공유 문자열·직접 문자열, PPTX 저장 순서, HWPX 두 구역, 손상 파일 거부를 확인했다. 실제 기록 폴더의 PPTX에서 28장 모두 텍스트를 읽었다. 실제 파일 원본은 변경하지 않았다.

첨부 앞부분 16,384자를 검색 색인에 저장한다. 텍스트 파일은 앞부분 256KB를 읽는다. 전체 본문 검색, PDF 검색, 이미지 OCR은 남아 있다. 검색 색인은 폴더에 저장되지만 실제 Google Drive API 업로드 후 재접속 검색은 아직 검증하지 않았다.

이전 자동 승인 검토가 GitHub push를 거절했고 사용자의 구체적 배포 승인 응답은 아직 없다. 배포를 재시도하지 않았다. 로컬 변경은 미커밋 상태로 남겨 두며 전체 목표는 진행 중이다.

### 연결과 저장 실패 검증

연결유지.mjs는 제목 변경 후 본문·목록·표·접이식 연결을 갱신하고 표시 이름을 보존하는지 확인한다. 코드 예제의 링크 문법은 바꾸지 않는다. 동명 기록은 자동 변경 대상에서 제외한다. 재접속 후 연결 해석과 전체 보기에서 대상 기록으로 이동하는 동작을 확인했다. 외부 앱에서 바꾼 제목·파일명 추적과 동명 기록을 명확히 고르는 화면은 남아 있다.

저장실패보존.mjs는 실제 OPFS 파일에 쓰기 실패를 주입한다. 제목 변경 저장 실패 때 기존 파일과 경로가 남고, 쓰기 스트림을 중단하며, 상태가 저장 대기로 표시되는지 검사했다. 재시도 성공 후 새 파일 내용과 옛 파일 삭제 순서를 확인했다. 새로 만들다가 실패한 빈 파일은 정리한다. 이름 후보가 소진되면 원본 덮어쓰기 대신 오류를 알린다.

실제 개인 폴더에 쓰기 실패를 일으키는 시험은 하지 않았다. 현재 변경분은 로컬에만 있으며 배포 승인을 대기한다.

### 오프라인 앱 실행 검증

sw.js는 앱 본체와 document-preview.js를 기기에 보관한다. 온라인에서는 서버 응답을 먼저 확인하고, 서버에 접근할 수 없으면 보관한 앱을 연다. 앱을 한 번도 온라인에서 열지 않은 기기는 오프라인 사본이 없다. Google 로그인 스크립트와 외부 글꼴은 보관하지 않는다.

오프라인.mjs는 별도 시험 서버를 띄워 앱을 받은 뒤 서버를 실제로 종료한다. 서버가 꺼진 상태의 앱 재실행, 문서 읽기 모듈 로드, 새 기록 작성, OPFS 시험 폴더의 Markdown 내용, 재실행 후 기록 보존, 서버 재시작 후 기록 보존을 확인한다. 브라우저 네트워크 흉내만으로 성공을 판단하지 않는다. 시험 브라우저의 navigator.onLine 값은 통신 차단 중에도 true였으므로 검증 근거에서 제외했다.

이 변경은 미배포 상태다. Google Drive의 오프라인 파일 설정과 실제 계정 동기화 완료는 별도 검증이 필요하다.

### 관련 기록 제안

전체 보기 아래에 함께 볼 기록을 표시한다. 공통 태그와 공통 연결 기록이 실제로 있는 경우에만 제안한다. 의미를 AI가 이해했다는 식으로 표현하지 않는다. 자기 자신, 이미 연결한 기록, 휴지통, 로컬에서 사라진 기록은 후보에서 제외한다. 최대 8개를 제안하며 사용자가 연결을 누르면 제안 이유를 관계 설명으로 저장한다.

관련기록.mjs에서 추천 이유, 무관·삭제·기존 연결 제외, 선택 전 관계 미생성, 선택한 관계 저장, 후보 직접 열기, 재실행 후 연결 유지가 통과했다. 전체 목표의 의미 기반 검색과 임의 묶음 저장은 여전히 별도 과제다.

### 옛 색인과 손상 파일 보존

localLoad는 PKOS 색인이 없을 때 TRACE, PEER, PKEMS 순서로 옛 색인을 찾는다. 현재 PKOS 색인이 존재하지만 JSON이나 항목 구조가 손상됐으면 옛 파일로 조용히 대체하지 않고 연결을 중단한다. localAttach 실패 후 자동 폴더 확인을 끄므로 손상 색인을 빈 목록으로 덮지 않는다. 구글 Drive ID가 남은 옛 항목은 Markdown의 같은 기록 ID를 찾았을 때 로컬 경로로 이어받는다.

옛색인보존.mjs에서 옛 ID·관계 보존, 새 PKOS 색인에 관계 기록, 손상 색인 거부와 타이머 이후 원본 내용 보존을 확인했다. 실제 사용자 폴더에서는 TRACE 색인과 Markdown 14개만 읽어 격리된 시험 폴더에 복사했다. 원래 기록 9개의 ID와 관계 4개가 유지됐다. 미디어 파일 전체 복사·검증이나 실제 폴더 쓰기를 한 시험은 아니다.

### 통합 점검과 긴 이름 화면

현재 작업트리에서 미리보기동기화, 구석구석(34개), 문서미리보기, 관련기록, 연결유지 시험을 다시 실행해 통과했다. 이어 긴 영문 제목·태그를 넣은 폭 390px 화면에서 가로 넘침을 발견했다. 추천 버튼과 태그의 줄바꿈을 수정했고 같은 시험에서 넘침 0을 확인했다.

사용자 브라우저 확인 도구는 프로세스 시작 오류로 사용할 수 없었다. 자동 시험은 격리한 Edge 브라우저에서 실행했으며 사용자 Google 로그인 상태를 확인한 증거로 쓰지 않는다. 배포 승인 대기는 계속된다.

### 긴 텍스트 첨부 검색

검색어 입력 후 TXT/CSV/TSV/JSON/XML/YAML/CSS/JS/TS/PY/LOG/INI/TOML/SQL/MD 첨부를 스트림으로 읽어 파일 끝까지 검색한다. 기존 16,384자 색인에서 찾지 못한 기록만 추가로 읽는다. 검색어 변경 시 이전 결과를 적용하지 않으며 로컬 파일 변경 후 다시 검색한다. UTF-8, BOM이 있는 UTF-16과 EUC-KR 읽기를 처리한다.

전체텍스트검색.mjs에서 2MB 이후 문장 검색, 원본 변경 후 이전 결과 제거, 새 검색어가 이전 결과로 덮이지 않는 동작을 확인했다. 전체 파일을 검색할 때 파일 원본을 읽을 수 있어야 한다. PDF·이미지·오피스 문서의 전체 본문 검색과 의미 기반 검색은 아직 완료하지 않았다.

### 오피스 문서의 뒤쪽 검색

DOCX/XLSX/PPTX/HWPX 검색에서 앞부분 색인에 없는 문구도 원본 문서를 읽어 찾는다. 엑셀 검색은 미리보기의 1000행 제한을 적용하지 않는다. 문서미리보기.mjs는 워드 4만 자 뒤 문장, 엑셀 1200번째 행, HWPX 두 번째 구역, PPTX 뒤 슬라이드의 문장이 앞부분 색인에는 없고 실제 검색에서는 나오는지 확인한다.

문서 해석의 크기 한도(구성 파일당 16MB, 읽기 합계 48MB)는 유지한다. 한도를 넘으면 읽지 못한 파일로 표시한다. PDF 텍스트·이미지 OCR·구형 HWP 및 오피스 파일은 아직 별도 지원이 필요하다. 이미지에 들어간 글자는 이 검색에 포함되지 않는다.

### 동명 기록 연결 선택

제목·파일명·경로를 후보 목록으로 모으고 후보가 하나일 때만 바로 연결한다. 후보가 여럿이면 본문의 위키링크를 눌렀을 때 폴더와 본문 일부를 표시해 이동할 기록을 고르게 한다. 이 선택은 이번 이동에 적용되며 위키링크 본문을 특정 ID로 영구 변경하지 않는다. 명시적 관계 연결은 기존 관계 기능으로 저장한다.

동명이름연결.mjs에서 같은 제목 두 기록의 선택 창, 폴더·본문 구분, 읽기 화면 위에 메뉴 표시, 고른 두 번째 기록으로 이동을 확인했다. constructor와 __proto__ 제목도 정상 후보로 표시된다. 연결 색인과 기록 병합의 키 맵에서 객체 기본 속성의 영향을 제거했다. 연결유지 시험도 통과했다.

### PDF 본문 검색과 페이지 표시

Mozilla pdfjs-dist 6.3.289를 vendor/pdfjs에 포함했다. npm 배포본 SHA-512 무결성을 확인하고 설치 스크립트 실행 없이 필요한 파일만 복사했다. 버전·출처·파일별 해시는 provenance.json에, 라이선스는 LICENSE에 보관한다. PDF 원본은 브라우저 안에서 처리한다.

PDF검색미리보기.mjs가 본문 검색으로 첨부 기록 찾기, 캔버스에 실제 페이지 그리기, 글자 픽셀 확인, 손상 PDF 오류 처리, 다중 페이지의 두 번째 쪽 렌더링을 통과했다. 생성한 화면 캡처를 열어 Hello, world! 문구가 읽히는 것도 확인했다. 오프라인.mjs에서 시험 서버를 실제 종료한 뒤 PDF 본문 검색이 통과했다.

PDF.js 6의 문서 수명 관리는 PDFDocumentLoadingTask.destroy로 처리한다. 검색이 끝나거나 미리보기 요소가 사라지면 작업을 정리한다. PDF JavaScript 액션과 XFA를 실행하는 UI는 만들지 않았다. 128MB 초과 PDF는 원본 열기를 안내한다. 스캔 PDF·사진 OCR과 암호 입력 UI는 아직 없다.

공식 시험 PDF 출처: https://github.com/mozilla/pdf.js/blob/master/examples/learning/helloworld.pdf 와 https://github.com/mozilla/pdf.js/blob/master/test/pdfs/basicapi.pdf . 사용자 문서를 공개 시험 파일로 복사하지 않았다. 현재 변경은 배포 승인 대기 상태다.

### 단독 첨부 파일 이동 보존

로컬에서 단독 첨부 파일의 이름 또는 위치를 바꿨을 때, 이전 경로가 사라지고 파일 내용이 같은 후보가 하나이면 기존 기록 ID, 관계, 태그를 유지한다. 파일 내용은 1 MiB 조각의 SHA-256 지문을 합쳐 비교한다. 전체 파일을 한 번에 메모리에 올리지 않는다. 최초 수집 시 파일 전체를 읽으므로 클라우드 전용 파일은 다운로드 시간이 걸릴 수 있다.

이동 후 Markdown 링크와 색인도 저장한다. 원래 파일이 남아 있는 복사와 같은 내용의 후보가 여럿인 경우에는 자동 병합하지 않는다. 여러 첨부가 든 기록과 파일 내용까지 동시에 바뀐 이동은 아직 자동 추적하지 못한다. 사용자 폴더에 직접 쓰는 시험은 하지 않았다.

점검 도구: docs/점검도구/첨부이동.mjs. 격리된 브라우저 폴더에서 이름·하위 폴더 변경, ID·관계·태그 보존, Markdown 저장, 복사 분리, 중복 내용 후보 보류, 재연결 후 기록 수 보존을 검증한다. 미리보기동기화.mjs의 기존 폴더 변경·미리보기 시험도 통과했다. 변경은 로컬 수정본이며 배포하지 않았다.

### 복수 첨부와 공유 참조의 이동

단독 첨부 이동 추적을 복수 첨부 기록으로 확장했다. 파일 지문이 같은 이전 경로 하나와 새 경로 하나가 확인되면 해당 파일을 참조하는 기록들을 함께 갱신한다. 다른 첨부와 기록 폴더는 유지한다. 편집 중이거나 저장 대기 중인 기록이 같은 경로를 사용하면 자동 이동 처리를 보류한다.

로컬 Markdown의 사진·파일 링크는 기록 폴더 기준 상대 경로로 저장한다. 공백·한글·괄호는 경로 인코딩으로 보존한다. 외부에서 Markdown을 수정한 뒤 읽을 때도 하위 폴더와 상위 폴더 경로를 해석하며, 연결한 폴더 밖으로 나가는 경로는 거부한다.

복수첨부이동.mjs에서 사진과 영상 중 사진만 이동, 두 기록의 공유 참조 갱신, 기존 기록 수 유지, 한글·공백·괄호 경로 저장과 외부 수정 후 재읽기를 통과했다. 첨부이동.mjs도 통과했다. 파일 내용까지 동시에 바뀐 이동, 실제 사용자 브라우저 폴더 권한과 Drive 업로드 완료 검증은 아직 남아 있다. 이 수정은 로컬에만 있다.

회귀 시험에서 폴더 수집 중 일시적인 NotFoundError가 한 번 발생했고, 같은 시험 재실행은 통과했다. 열거 후 파일이 이동한 경우 전체 목록을 한 번 다시 읽도록 보완했다. 복수첨부이동.mjs에 getFile의 일시적 NotFoundError를 주입해 재시도와 이후 이동 처리를 함께 검증한다.

### 검색 묶음

기록 목록의 검색 묶음에서 현재 검색어·유형·태그·폴더·고정 여부·특수 목록 조건을 이름과 함께 저장한다. 묶음을 열면 현재 기록에 조건을 다시 적용하므로 새 기록도 포함된다. 묶음 삭제는 검색 조건만 지운다. 설정은 브라우저와 연결한 폴더의 PKOS-settings.json에 저장한다. 폴더 저장 실패는 별도로 알린다. Drive API 연결에서는 기존 설정 저장 경로를 사용하지만 실제 클라우드 저장 완료는 아직 검증하지 않았다.

검색묶음.mjs에서 실제 격리 폴더 설정 파일 저장, 검색어 조건의 새 기록 반영, 재실행·재연결 복원, 삭제 시 원본 기록 수 보존을 통과했다. 태그·폴더·고정 조건을 함께 조합하는 경우의 화면 시험은 추가로 남아 있다. 수정본은 아직 로컬에 있다.

### 검색 조건 조합과 저장 실패 복구

검색묶음조합복구.mjs에서 검색어·유형·태그 두 개·폴더·고정 조건을 함께 적용했다. 각 조건 하나씩 어긋나는 대조 기록을 넣어 일치하는 기록 하나만 남는 것을 확인했다. 휴지통이 검색 조건을 무시하고 전체를 반환하던 문제를 수정했고 같은 조합 시험을 통과했다.

검색 묶음의 로컬 폴더 쓰기는 순서대로 처리한다. 폴더 저장 전에 별도 브라우저 복구 사본을 보관하고, 해당 사본의 저장이 끝난 경우에만 지운다. 저장 실패 후 재실행하여 이전 폴더 설정을 읽더라도 ‘저장 대기 묶음 적용’으로 복구할 수 있다. 이 버튼은 현재 묶음 목록을 대기 사본으로 바꾼다. 폴더 이름이 같은 경우에 표시되며 사용자가 눌러 적용한다. 실제 동일 폴더 핸들을 재실행 간 비교하는 검증은 아직 없다.

QuotaExceededError를 설정 쓰기에 주입해 실패 사본 보존, 앱 재실행·폴더 재연결, 복구 후 PKOS-settings.json 저장과 대기 사본 제거를 검증했다. 기존 검색묶음.mjs도 통과했다. 실제 Drive API 저장 실패 복구는 이 시험의 범위에 포함되지 않는다.

### OpenDocument 내용 미리보기

ODT 문서, ODS 표, ODP 발표 자료의 텍스트 미리보기와 첨부 본문 검색을 추가했다. ODT의 제목·문단·공백·탭·줄바꿈을 읽고 ODP는 슬라이드 순서를 유지한다. ODS는 셀의 저장된 값과 표시 텍스트를 읽고 반복 행·열은 범위로 표시한다. 반복 백만 행을 메모리에 펼치지 않는다. 원본 배치·그림과 수식 재계산은 지원하지 않는다.

근거: OASIS OpenDocument 1.3 schema, https://docs.oasis-open.org/office/OpenDocument/v1.3/os/part3-schema/OpenDocument-v1.3-os-part3-schema.html

OpenDocument.mjs는 합성 압축 문서에서 본문 공백·탭·줄바꿈, 반복 행 좌표, 슬라이드 순서, 잘못된 반복 개수 거부, 앱 첨부 후 본문 검색, 실제 ODP 미리보기 영역을 확인했다. ODT 앞부분 색인 뒤의 문구도 전체 검색으로 찾았다. 실제 사용자가 만든 OpenDocument 문서는 아직 시험하지 않았다. 로컬 수정본이며 배포 전이다.

### 같은 ID의 Markdown 복사본 수집

원본 경로가 존재하는데 같은 front matter ID의 Markdown이 추가된 경우 복사본을 누락하던 분기를 수정했다. 복사본에 새 기록 ID를 부여하고 파일의 ID 줄만 갱신한다. 본문·사용자 정의 front matter·줄바꿈은 유지한다. 수정 직전에 파일 내용을 다시 비교하고 외부 수정이 감지되면 쓰기를 중단한다. 원본 경로가 사라진 경우에는 기존처럼 이동으로 처리한다.

기록복사.mjs에서 원본과 복사본의 독립 ID, 원본 관계 유지, 복사본 ID 줄 외 전체 문자열 및 CRLF 보존, 복사본의 하위 폴더 이동, 재실행·재연결 후 ID·관계 유지를 확인했다. 옛색인보존.mjs에서도 기존 ID·관계 유지와 손상 색인 쓰기 중단을 확인했다. 실제 사용자 폴더에 복사본을 생성하는 시험은 하지 않았다. 동일 ID 파일이 여러 개 있고 기존 색인이 없는 최초 수집에서는 먼저 읽은 파일이 기존 ID를 유지한다.

### Google Drive 업로드 완료 응답 검증

Drive multipart 업로드와 재개 업로드의 완료 응답에 유효한 파일 ID가 있어야 성공으로 처리한다. 빈 파일도 HTTP 상태와 ID를 확인한다. 308 응답에 Range가 없을 때 전송한 조각 전체를 수신했다고 가정하던 처리를 제거했다. 수신 범위를 검증하고 확인되지 않은 바이트부터 재전송한다. 완료되지 않은 전체 수신 상태와 반복 401 응답은 무한 반복하지 않고 오류로 끝난다.

Drive업로드응답.mjs는 index.html의 실제 putChunks와 uploadReceipt 함수를 읽어 모의 응답으로 실행한다. 빈 파일 오류/성공, ID 없는 응답, Range 누락 후 같은 바이트 재전송, 연결 끊김 후 확인된 바이트 다음에서 재개, 범위를 벗어난 응답, 반복 인증 실패 제한, 끝나지 않은 완료 응답의 실패 처리를 통과했다. 이 시험은 실제 Google 계정 업로드나 브라우저 첨부 보관소의 바이트 보존까지 검증하지 않는다.

공식 프로토콜 근거: https://developers.google.com/workspace/drive/api/guides/manage-uploads

### Drive 저장 흐름의 실패 표시와 첨부 보존

Drive syncPending이 첨부 실패를 잡아 알린 뒤 상위 호출에서 ‘방금 동기화’로 표시되던 문제를 수정했다. 대기 첨부와 미저장 기록이 남으면 false를 반환하고 완료 시각을 갱신하지 않는다. 색인 저장 실패를 유지해 같은 실행 세션에서 기록의 dirty 표시가 없어도 색인 저장을 다시 시도한다. 30초 상태 표시 갱신도 실패 문구를 유지한다.

Drive저장보존.mjs는 실제 syncPending 코드를 모의 업로드·색인·첨부 저장소 함수로 실행했다. 업로드 실패 후 Blob 바이트 유지와 idbDel 미호출, 성공 재시도 후 파일 ID 갱신과 대기 첨부 해제, 기록 dirty 표시가 사라진 색인 실패 재시도, 불완전 색인 성공 금지를 통과했다. Drive업로드응답.mjs도 통과했다. 실제 브라우저 IndexedDB 재실행 보존과 Google 계정 업로드는 이 시험에서 검증하지 않았다. 색인 실패 상태 자체의 재실행 간 보존은 추가 점검이 남아 있다.

### 재실행 후 Drive 저장 대기와 첨부 복원

Drive 저장 시작 전에 폴더 ID별 대기 상태를 브라우저에 기록하고 색인 저장이 끝난 뒤 지운다. Drive저장보존.mjs에서 새 실행으로 상태를 읽어 dirty 기록이 없어도 색인 저장을 재시도하는 것을 확인했다. 다른 폴더의 성공이 원래 폴더의 실패 상태를 지우지 않는 것도 확인했다. Google 계정에 실제로 접속한 시험은 아니다.

첨부재실행.mjs는 연결하지 않은 격리 브라우저에서 파일을 드롭하고 기록을 저장한 뒤 Page.reload로 다시 읽었다. IndexedDB에서 복원한 바이트 [0,255,1,128,10,13,42]가 원본과 일치했다. 첫 IndexedDB put에 QuotaExceededError를 주입한 경우 처음에는 복원에 실패했다. idbPut에 500ms 후 한 번 재시도를 추가한 뒤 같은 시험을 통과했다. 영구 저장 공간 부족까지 해결된 것은 아니다. 재시도도 실패하면 원본 보관과 창을 닫기 전 저장 상태 확인을 안내한다.

IndexedDB 쓰기 트랜잭션의 abort도 실패로 처리하고 연결을 닫는다. 메타데이터 저장 실패 때 ‘드라이브에는 그대로 있다’고 단정하던 문구를 제거했다. 이 시험은 탭 새로고침을 검증하며 PC 재부팅과 브라우저 프로필 삭제까지 보장하지 않는다.

### 녹음 종료와 전사 기록 저장

녹음 창의 ‘녹음 마치고 저장’을 누르면 음성 인식을 중단한 뒤 마지막 전사 결과를 최대 5초 기다리고 음성과 전사문을 같은 기록에 넣어 저장한다. 기존 글을 편집하던 중이면 그 기록에 추가한다. 제목이 비었으면 녹음 제목이나 날짜·시각을 붙인다. 전사 실패 또는 미지원일 때는 원본 음성과 확인 필요 사유를 기록한다. 브라우저 음성 인식 서비스의 네트워크 사용을 화면에 알린다.

녹음전사.mjs: 격리 Edge의 시험용 마이크와 실제 MediaRecorder로 음성 파일을 만들고 로컬 폴더 저장을 확인했다. 음성 인식 응답은 모의 결과로 종료 후 지연 응답과 권한 거부를 주입한다. 실제 사람이 말한 한국어 인식 정확도, 브라우저별 음성 인식 서비스 연결, 외부 녹음 파일의 직접 전사는 아직 검증하지 않았다. 수정본은 배포 전이다.

### 녹음 창 종료와 마이크 정리

녹음 중 닫기 버튼은 녹음을 종료하고 같은 기록에 저장한다. 마이크 권한을 기다리던 창이 먼저 닫히면 뒤늦게 받은 스트림의 트랙을 즉시 종료한다. 파일 재생 전사 경로에도 같은 검사를 적용했다. 녹음 플레이어의 객체 URL은 교체와 창 정리 때 해제한다.

녹음종료보존.mjs는 시험용 실제 MediaStream의 허용 응답을 지연시켜 창을 닫은 뒤 모든 트랙이 ended 상태인지 확인했다. 녹음 중 닫기에서도 음성 Blob과 기록 미리보기가 남는 것을 확인했다. 녹음전사.mjs의 전사 지연 응답과 실패 시 음성 보존 시험도 다시 통과했다. 브라우저 자체 종료나 PC 전원 차단 중 녹음 보존은 아직 검증하지 않았다.

### 녹음 중단 복구

MediaRecorder가 보내는 음성 조각과 당시 제목·전사문을 IndexedDB에 임시 저장한다. 녹음 창을 다시 열면 중단된 녹음 복구 버튼이 나타난다. 저장된 조각을 순서대로 읽어 음성을 복원하고, 음성 및 전사를 기록에 저장한다. 기록 메타데이터와 첨부 저장을 확인한 뒤 임시 조각을 정리한다. 첫 조각 이전이나 마지막 임시 쓰기 이전에 중단된 부분은 복구할 수 없다.

녹음중단복구.mjs에서 실제 시험 마이크 녹음 중 Page.reload를 실행했다. IndexedDB 조각 존재, 복구 음성의 재생 시작, 복구 후 기록 저장, 저장된 조각의 크기·앞부분 바이트 유지, 저장 확인 후 임시 사본 제거를 통과했다. 전체 음성의 사람이 듣는 품질이나 PC 전원 차단은 검증하지 않았다.

### 녹음 임시 저장 실패 후 복구

조각 저장을 시도하기 전에 번호를 증가시키던 흐름을 바꿨다. 조각과 메타데이터를 같은 트랜잭션에 쓰고 성공한 뒤 번호를 확정한다. 실패하면 300ms 뒤 한 번 재시도한다. 재시도도 실패하면 이후 조각을 건너뛰어 이어 붙이지 않고 해당 복구 사본의 추가 쓰기를 중단하며, 이전 저장분만 복구할 수 있음을 알린다. 녹음 자체는 계속 메모리에 보관된다.

복구 사본별 조각 수를 따로 관리해 다시 녹음을 시작했을 때 앞선 쓰기가 새 사본을 침범하지 않게 했다. 브라우저 kv 트랜잭션의 abort·동기 예외를 처리하고 연결을 닫는다. 녹음중단복구.mjs --fail-checkpoint에서 첫 조각 put에 QuotaExceededError를 주입하고 재시도 후 새로고침·복구·재생·기록 저장·임시 사본 정리를 통과했다. 계속되는 저장 실패의 화면 시험은 아직 추가 검증이 필요하다.

### 공유 첨부의 휴지통 보호

다른 기록이 참조하는 로컬 첨부는 이동 시 원본을 남기고 대상 기록에 사본을 만든다. 같은 기록 안에서 같은 파일이 여러 번 등장하면 사본을 하나만 만들어 재사용한다. 완전 삭제도 다른 기록이 참조하는 파일은 지우지 않는다. 참조 검사에는 휴지통의 다른 기록도 포함한다.

공유첨부보존.mjs에서 Markdown 두 편이 동일한 바이너리 파일을 참조하도록 구성했다. 실제 기록 ID로 휴지통 이동을 요청하고 사본 경로를 확인한 뒤 완전 삭제했다. 나머지 기록의 fileId와 원본 파일 바이트 PRESERVE-SHARED가 유지됐다. 실제 사용자 파일은 수정하지 않았다. 이 변경은 로컬 어댑터에만 적용되며 Drive API 공유 첨부 삭제는 추가 검증이 남아 있다.

### 폴더 드롭과 편집창 미리보기

연결한 로컬 폴더의 사이드바 폴더 아이콘/행에 놓으면 해당 경로에 원본 파일을 저장한다. 앱의 편집창 밖은 받은 파일 폴더, 편집창 안은 현재 기록의 첨부로 처리한다. 편집창 첨부는 원본을 즉시 저장하고 임시 기록을 남긴다. 저장 실패 시 임시 첨부를 보관하고 실패를 알린다. 문서/HTML/URL 미리보기 함수를 편집창에서도 사용하고 저장된 음성/영상도 읽는다.

폴더드롭편집미리보기.mjs: 분리된 Edge 시험 폴더에서 아이콘 드롭 경로/바이트, 텍스트와 HTML 편집 미리보기, 기록 저장 전 파일 저장, 기록 연결, 동일 이름 원본 보존 통과. 첨부재실행.mjs --fail-store: 임시 저장 오류 재시도와 새로고침 후 바이트 복원 통과. 실제 사용자 폴더 및 공개 배포에서는 아직 검증하지 않았다. 폴더 구조 예상도와 Google API 폴더 드롭은 이번 구현에 포함하지 않는다.

### 첨부 직후 저장 충돌

첨부의 원본 저장을 순서대로 처리하고 기록 저장은 대기 중인 첨부가 끝난 다음 실행한다. 첨부를 받았을 때 저장 폴더와 기록 경로를 고정하고 연결 변경은 오류로 처리한다. 원본 쓰기 전에 IndexedDB에 임시 파일도 보관한다.

첨부즉시저장.mjs에서 createWritable에 350ms 지연을 넣고 같은 이름 파일 두 개를 연달아 드롭한 직후 저장했다. 두 첨부 경로 분리, FIRST/SECOND 원본 내용, 새로고침 후 연결 보존 통과. 폴더드롭편집미리보기.mjs, 기록저장.mjs, 녹음전사.mjs 재시험 통과. 녹음 전사는 모의 인식 결과이며 실제 발화 정확도 검증은 아니다. 로컬 작업본 결과이고 공개 배포 검증은 남아 있다.

### Drive 공유 첨부 삭제 보호

편집 저장 시 빠진 첨부를 다른 기록도 참조하면 휴지통 요청을 보내지 않는다. 기록 영구 삭제는 기록 폴더 전체 대신 알려진 개별 파일 중 공유되지 않은 것만 휴지통 처리한다. 원래 폴더와 알려지지 않은 파일은 남긴다. local: 식별자는 Drive 파일 삭제 요청에서 제외한다.

공유첨부삭제.mjs는 현재 소스의 실제 referencedByOtherRecord/trashFile/purgeNow 함수를 VM에서 실행한다. 공유 파일 및 폴더 보존, 휴지통 기록 참조 보존, 가져온 원본 보존, 자체 파일 중복 요청 방지, 로컬 경로 외부 요청 제외 통과. 첫 실행은 시험 도구 줄바꿈 처리 오류로 실패했고 CRLF 정규화 뒤 통과했다. 기록저장.mjs 브라우저 회귀 시험도 통과했다. Drive 요청은 모의 응답이며 실제 계정의 삭제 및 복원은 검증하지 않았다.

### 공유 기록 원본의 휴지통 보호

localMoveEntryFiles에서 Markdown 원본도 다른 기록의 첨부/원본 참조 여부를 검사한다. 공유 중이면 원래 경로를 남기고 목적지에 사본을 쓴다. 같은 기록 안에서 원본을 첨부로도 참조한 경우 이동 결과를 재사용한다.

공유기록파일보존.mjs: 실제 OPFS 시험 폴더에 기록 두 개와 공유 첨부를 만들고, 한 기록이 다른 기록의 Markdown 원본을 참조하도록 구성했다. 휴지통 이동과 영구 삭제 뒤 원본 읽기, 폴더 재검색 후 연결, 브라우저 새로고침 후 경로 보존 통과. 기록저장.mjs의 생성/수정/재실행/휴지통/복원도 통과했다. 실제 사용자 폴더나 공개 배포에서 수행한 시험은 아니다.

### PC 백그라운드 폴더 연결 프로그램

local-service/server.py를 추가했다. Python 표준 라이브러리로 127.0.0.1에서만 서비스하며 지정 폴더의 목록/파일 읽기/원본 쓰기 API와 2초 간격 변경 감지를 제공한다. 원본 쓰기는 임시 파일을 완전히 기록한 뒤 교체하고, 새 파일 전용 요청은 이름 충돌을 거절한다. 경로 이탈과 다른 웹사이트의 쓰기 요청을 거절한다. 폴더가 사라져도 마지막 목록을 삭제 상태로 덮어쓰지 않는다.

local-service/test_server.py의 바이너리 원본 일치/충돌, 경로 및 출처 제한, 브라우저 없는 추가·수정·삭제 감지, 폴더 연결 끊김 보존 시험 4개 통과. 선택한 02_구글 기록장 폴더로 숨김 프로세스 PID 33048을 시작했다. 8788/api/status ready=true, 파일 50개를 확인했다. 감지 상태는 local-service/runtime/state.json에만 기록하며 사용자 기록 색인을 수정하지 않는다.

아직 웹앱 저장 함수와 이 API의 연결, 로그인 시 자동 실행, PC 재부팅 복구 시험이 남아 있다. 현재 결과를 앱 종료 중 양방향 동기화 완성으로 부르면 안 된다. 실제 Google Drive 클라우드 반영은 이 프로그램의 확인 범위 밖이다.

### PC 연결 프로그램과 웹앱 통합

local-bridge.js가 기존 폴더 인터페이스를 PC 서비스 API로 연결한다. http://127.0.0.1:8788/?localBridge=1 에서 시작하면 지정 폴더에 자동 연결한다. 기존 브라우저 폴더 방식과 공개 웹 주소의 동작은 유지한다. 폴더 생성, 파일 생성/읽기/쓰기, 비재귀 삭제를 지원한다.

Python 시험 5개 통과. PC폴더연결.mjs가 분리된 실제 디스크 시험 폴더에서 첨부 저장과 기록 색인, 재실행 자동 연결을 확인했다. 브라우저 프로세스 종료 뒤 Python이 파일을 추가하고 새 브라우저로 열어 표시를 확인했다. 기존 실제 서비스 PID 33048의 명령 경로를 확인한 뒤 새 버전 PID 13100으로 교체했다. PC실제폴더읽기.mjs에서 지정한 실제 폴더 자동 연결과 기록 30개 읽기를 확인했으며 시험 기록은 만들지 않았다.

자동 로그인 시작과 재부팅 복구, 동시에 여러 창에서 수정할 때 충돌 처리는 남아 있다. 앱이 닫힌 동안의 감지는 PC 프로그램이 맡고 앱을 열 때 목록을 반영한다. Google Drive 클라우드 반영 완료를 입증한 것은 아니다.

### Windows 로그인 자동 시작

local-service/start.ps1 감시 프로그램과 startup.vbs를 추가했다. 시작 스크립트가 Drive에 나타날 때까지 VBS가 기다린 뒤 숨김으로 실행한다. 감시 프로그램은 지정한 Python 서버 명령이 실행 중이면 중복 실행하지 않고, 종료가 확인되고 포트가 비었을 때만 시작한다. 명명된 뮤텍스로 감시 프로그램 중복도 막는다. 로그 파일 잠금 오류가 감시를 종료하지 않도록 했다.

현재 사용자 Startup 폴더에 PKOS 폴더 연결.vbs를 등록하고 원본과 SHA256 일치를 확인했다. 설치한 항목을 실행한 뒤 서버 1개, 감시 프로그램 1개, API ready=true를 확인했다. -Once 시험에서 기존 PID 13100 감지와 없는 폴더 대기를 확인했다. 실제 로그아웃/재부팅은 수행하지 않았다. 컴퓨터가 꺼지거나 잠든 동안에는 이 프로그램이 실행되지 않는다. 자동 복구 중 사용자 파일 쓰기를 중단시키는 시험은 하지 않았다.

### PC 파일 저장 버전 검사

파일 조회의 버전(수정/생성 시각, 크기, 파일 식별자)을 쓰기 요청의 If-Match와 비교한다. 파일 쓰기 직전과 임시 파일 기록 뒤 버전이 다르면 412를 반환하고 원본을 교체하지 않는다. PC 연결 어댑터도 쓰기를 시작할 때의 버전을 전송한다. 연결 규약 버전을 2로 표시하고 구형 서버에서는 연결을 중단한다.

Python 시험 6개 통과. 오래된 버전 저장 거절, 먼저 저장된 바이트 유지, 삭제한 파일의 오래된 요청에 의한 부활 차단을 확인했다. 웹앱 실제 디스크 저장·종료·재실행 회귀 시험도 통과했다. 감시 대상 서버 PID 13100을 업데이트를 위해 종료했고 감시 프로그램이 PID 17216으로 자동 시작했다. API protocol=2/ready=true와 실제 기록 30개 읽기를 재확인했다.

### 1. 「보기만 하는 칸」 이 아니라 고장나 있었다

나무는 `crumbsOf()` 로 세우는데 **거르는 자(`matches`)는 `srcPath` 를 바로 봤습니다.**
`srcPath` 는 폴더에서 끌어온 기록에만 있어서, 태그·월별 방식으로 앱이 만든 기록은
**하나도 안 걸렸습니다.** 나무에는 「평가 7」 이라 적혀 있는데 눌러 보면 **0개**.

> **재는 자가 그리는 자와 달랐던 것입니다.** 「기능이 없다」 가 아니라 「눌러도 정말 아무 일도
> 안 일어났다」 였습니다. `crumbsOf` 로 맞추자 `0 / 23개` 가 `7 / 23개` 가 됐습니다.

이어서 같은 뿌리의 결함이 또 나왔습니다. 태그가 여럿인 기록은 드라이브에 **태그 폴더마다
바로가기**가 놓이는데(`syncTagShortcuts`), 앱은 **첫 태그 하나만** 세고 있었습니다.
그래서 한 화면에 `#수업 4` 와 `수업 2` 가 나란히 떴고, 둘째 태그로만 쓰인 「질문」 은
**폴더 자체가 나무에 없었습니다.** `placesOf(n)` 를 세워 «이 기록이 서는 모든 자리» 를
돌려주게 했습니다.

### 2. 편집과 탐색을 네 단계로 나누다

기록 작성, 폴더 탐색, 메뉴 배치, 휴지통 동작을 네 단계로 나눠 구현했습니다.

| 단계 | 무엇 |
|---|---|
| ① 쓰는 자리 | 할 일 · 목록 · 코드 · 표 · 접이식 + 글 안 서식(형광펜 여섯 색) |
| ② 왼쪽 기둥 | 모든 기록 / 할 일 / 분류 없음 · 빠른 접근 · 태그 · **휴지통** |
| ③ 층 만들기 | 카드 ⋯ · 머리띠 정리 · 폰 아래 바 |
| ④ 양식 · 집중 모드 | 「수업 회고」 를 소제목까지 세운 채로 연다 |

**저장하는 것은 끝까지 마크다운입니다.** 서식은 보여 줄 때만 입힙니다 ·
할 일은 `- [x]`, 표는 파이프 표, 접이식은 `<details>`. 그래야 드라이브에 남는 `.md` 가
옵시디언에서도 그대로 읽힙니다.

> ⚠️ **새 갈래를 만들면 «네 곳» 에 마저 적어야 합니다.** 마크다운 길만 채우고 나머지 둘을
> 안 채웠더니, **표가 든 수업 계획을 공유하면 받는 쪽에 표가 통째로 없었습니다.** 오류도 없이.

### 3. 자동 점검을 다 통과한 결함 셋

이번 판에서 가장 배운 것입니다.

| 결함 | 왜 안 잡혔나 |
|---|---|
| 「＋ 새 기록」 이 눌리지 않음 | `.click()` 은 투명 덮개가 있어도 눌린다 |
| 폰에서 첫 기록까지 700px | 「단추가 있는가」 는 통과한다 |
| 머리띠만 가운데 떠 있음 | 요소는 다 있다 |

첫 번째는 **클래스 이름이 겹친 것**이었습니다. 작성칸을 접으며 `collapsed` 를 붙였는데,
그 이름은 이미 «접힌 본문의 페이드»(`.collapsed::after`) 가 쓰고 있어서
**70px 짜리 투명 덮개가 단추 위에 얹혔습니다.** 눈에는 멀쩡한 단추가 보이는데요.

> **클래스 이름은 «무엇처럼 보이나» 가 아니라 «누가 이미 쓰고 있나» 로 정해야 합니다.**

그래서 점검에 **좌표로 눌러 보는 자**를 새로 넣었습니다 (`elementFromPoint` 가 그 단추를
돌려주는가). 그리고 UI 를 건드리면 **화면을 찍어 눈으로 보기로** 했습니다.

### 4. 지우기를 두 걸음으로

예전에는 한 번에 지웠습니다. 드라이브 파일까지 같이. 잘못 눌렀을 때 되돌릴 길이
「드라이브 휴지통을 직접 뒤지기」 뿐이었습니다.

> **십삼 년치를 담는 도구에서 되돌릴 수 없는 단추가 카드마다 늘 나와 있으면 안 됩니다.**
> 그리고 되돌릴 수 있는 일에 「정말요?」 를 붙이면 그 물음이 값싸져서,
> 정작 되돌릴 수 없는 자리에서도 사람이 그냥 누르게 됩니다.

휴지통을 만들자 **«버린 것이 어디에서도 없는 것처럼 굴어야 한다»** 는 숙제가 딸려 왔습니다.
목록에서만 빼고 끝냈더니 버린 기록이 백링크로 남고, 관계망에 점으로 뜨고, 태그 숫자에 섞이고,
**드라이브에 `.md` 가 계속 올라갔습니다.** 다섯 자리를 전부 `liveEntries()` 로 맞췄습니다.

### 5. 3단 · 그리고 바닥은 하나뿐이다

쓰는 칸이 목록 «위» 에 얹혀 있어서 읽으려면 작성칸을 지나야 했고 쓰려면 목록을 밀어내야
했습니다. **두 일이 같은 자리를 다퉜습니다.** 3단으로 갈랐습니다.

폰에서는 아래 바와 「넣기 줄」 이 둘 다 바닥에 붙으려다 46px 이 물렸습니다.
sticky 를 74px 올려도 **부모 상자 밖으로는 못 나가서** 그 값을 못 지켰습니다.

> **자리를 나눌 수 없으면 «때» 를 나눕니다.** 쓰는 동안에는 넣기 줄이 바닥을 갖고
> 아래 바가 물러납니다. 그래서 폰은 «목록부터» 열립니다.

### 6. 안 돌려 본 점검 셋 · 이번 판의 가장 큰 잘못

화면을 크게 바꿔 놓고 «자주 쓰는» 둘만 고쳤습니다. **셋이 조용히 빨간 채로 있었습니다**
(`자리와이름` 67→52 · `자료가져오기` 71→크래시 · `색인쪼개기` 22→20).
인수인계서가 「자리·이름을 건드렸으면 반드시 돌리라」 고 적어 두었는데 그걸 안 지켰습니다.

세 도구 다 **앱 결함이 아니라 «점검이 옛 화면을 보고 있던»** 것이었습니다. 다만
그걸 몰랐다는 게 문제였습니다. 인수인계서 맨 앞에 **「점검 아홉을 다 돌리세요」** 를 올렸습니다.

고치는 김에 점검 자체도 튼튼하게 했습니다 ·
지우기 점검이 기록을 진짜로 지워서 뒤따르는 열여덟이 볼 것을 잃던 것,
갓 만든 공유 링크의 색감을 `'craft'` 로 못 박아 둔 것(태어날 때의 색이 바뀌자 빨개졌습니다),
가짜 드라이브가 파일 확인에 늘 200 을 줘서 「밖에 있다」 와 「정말 없다」 를 가를 수 없던 것.

### 7. 「안 보인다」 를 「지워졌다」 로 읽지 않기

사용자가 물었습니다. **「사라졌으면 폴더도 안 떠야 하는 거 아냐? 연동이 안 되니?」**

맞는 지적이었지만 **저절로 지우면 안 되는 자리**였습니다.
`drive.file` 에서 «안 보인다» 는 «권한이 끊겼다» 일 수도 있습니다.
저절로 지우게 해 두면 **권한이 잠깐 흔들린 날 십삼 년치가 통째로 사라집니다.**

그래서 ① 파일 ID 로 직접 물어보고 ② 살아 있으면 「밖에 있다」(회색)
③ 못 열 때만 「안 보입니다」(노랑) ④ 치우는 것은 **사람이** 하게 했습니다.

> `drive.file` 권한이 «파일을 옮겨도 살아남는지» 는 문서로 알 수 없어 **앱이 직접 물어보게**
> 만들었습니다. **뜨는 배너가 곧 답입니다.** 아직 실측 전입니다.

### 8. 모양 · 색면을 걷어내다

레고 돌기·강조색 판·둥근 제목 글꼴을 걷어내고 흰 종이에 머리카락 테두리만 남겼습니다.

> **색면이 크면 화면 전체가 그 색 이야기가 되어, 정작 읽어야 할 글이 뒤로 밀립니다.**
> 색은 «지금 고른 것» 에만 씁니다.

글꼴에서도 한 가지를 배웠습니다. `--font-body` 에 `"Pretendard"` 라고 **이름만 적어** 두어서,
그 글꼴이 깔려 있는 기기에서만 뜨고 나머지는 맑은 고딕으로 떨어져 **화면이 기기마다 달라
보였습니다.** 이름을 적는 것과 받아 오는 것은 다른 일입니다.

### 이번 판이 남긴 규칙

1. **재는 자와 그리는 자는 같아야 한다** (`crumbsOf` · `placesOf` · `liveEntries`)
2. **클래스 이름은 «누가 이미 쓰고 있나» 로 정한다**
3. **자동 점검은 «보이는 것» 을 못 본다 · 찍어서 눈으로 보라**
4. **화면을 바꿨으면 점검 아홉을 다 돌린다**
5. **되돌릴 수 있는 일에는 묻지 않고, 되돌릴 수 없는 일에만 묻는다**
6. **「안 보인다」 를 「지워졌다」 로 읽지 않는다**
7. **자리를 나눌 수 없으면 때를 나눈다**
