# 변경내역

## 2026-09-10 · 이름 바꾸기 · 고장 난 곳 · 되돌리기 · 삭제 · 의견 받기

쓰다가 걸린 것을 그 순서대로 고쳤습니다. 문구만이 아니라 실제로 안 되던 것들입니다.

### 고친 것 (버그)

| 무엇 | 왜 그랬나 | 어떻게 |
|---|---|---|
| 🎯 **집중** 을 누르면 흰 화면만 나왔다 | 집중 모드가 가운데 칸 «안의 것» 만 감추고 칸 자체는 안 감췄다. 빈 칸 하나가 화면 높이만큼 서 있고 적는 칸은 그 아래로 밀려났다 | `.listcol` · 손잡이 · 가림막을 칸째로 감춘다. 넓은 화면에서 오른쪽 칸에 걸려 있던 «화면에 붙어 구르는» 설정도 집중일 때는 되돌린다 |
| 📚 **자료 인용** 을 넣으면 안내 글자가 겹쳐 찍혔다 | ① 인용을 «제자리에 갈아 끼우는» 길에서 안내 글자를 다시 셈하지 않았다 ② 셈하는 함수가 «글자와 덩어리» 만 봐서, 틀만 먼저 서는 인용·목록·소제목은 여전히 «비었다» 가 됐다 | 두 곳 다 고쳤다. `hasPaperContent` 는 빈 글줄이 아닌 것이 하나라도 서 있으면 «쓰기 시작한 종이» 로 본다 |
| 이름 뒤 조사가 틀렸다 (「첫 시험 기록」**를**) | 조사를 글자로 박아 두었다 | `josa()` 를 두고 받침을 보고 고른다. 알림 여덟 곳에 적용 |

### 새로 된 것

- **되돌리기 · 다시 하기** — `Ctrl+Z` · `Ctrl+Shift+Z` (`Ctrl+Y` 도 됩니다). 편집 줄에 ↶ ↷ 단추도 섰습니다.
  브라우저가 스스로 해 주는 되돌리기는 «사람이 친 글자» 만 셉니다. 사진·녹음·손 메모처럼
  코드가 넣은 덩어리는 그 셈에 안 들어가서, 사진을 넣고 `Ctrl+Z` 를 누르면 사진은 그대로 있고
  엉뚱한 글자만 지워졌습니다. 이제 종이의 상태를 직접 한 장씩 찍어 둡니다.
  글자는 0.45초 쉴 때마다 한 장, 사진·삭제·자리 옮김은 그 자리에서 바로 한 장입니다.
- **삭제** — 지우는 길이 카드의 ⋯ 안에만 있었고, 가운데 칸에서는 그 ⋯ 마저 마우스를 얹어야
  나타났습니다. 「삭제 기능이 없다」 는 말을 들은 까닭입니다.
  - 고치는 중일 때 작성칸 머리줄에 **🗑️ 삭제** 가 섭니다. 확인 창에서 «휴지통으로» 와 «완전히 삭제» 를 고릅니다
  - 카드 ⋯ 에 **완전히 삭제** 를 함께 두었습니다 (전에는 휴지통 안에서만 보였습니다)
  - 카드 위에서 **오른쪽 단추** 로도 같은 메뉴가 열립니다
  - 가운데 칸의 ⋯ 는 늘 보입니다 (흐리게 서 있다가 얹으면 진해집니다)
  - **완전히 삭제** 는 드라이브의 `.md` 와 첨부 자료까지 휴지통으로 보냅니다. 확인 창이 반드시 한 번 뜹니다
- **왼쪽 폴더에서 오른쪽 단추** — 📂 드라이브에서 폴더 열기 · 🔗 폴더 주소 복사 ·
  📄 여기만 모아 보기 · 🗑️ 이 폴더의 기록 N편 삭제 (휴지통 / 완전히).
  폴더 ID 를 아는 줄은 바로 열리고, 이름길만 아는 줄은 뿌리부터 찾아 내려갑니다.
  **보러 가는 길에서 폴더를 새로 만들지는 않습니다.**
- **가운데 목록 칸만 접기** — 머리줄의 `‹` 로 접고, 남는 세로 띠로 폅니다.
  ☰ 는 «기둥 → 목록» 순서로 걷는 손잡이라 「폴더 나무는 두고 목록만」 이 안 됐습니다. 접은 것은 기기에 남습니다.
- **이름표를 누르면 홈으로** — 좁혀 본 것 · 검색 · 태그를 풀고 모든 기록으로 돌아갑니다.
  쓰던 글은 건드리지 않습니다.
- **💬 의견 보내기** — 오른쪽 아래. 질문 · 개선 의견 · 오류를 그 자리에서 적어 보냅니다.
  받는 자리는 구글 시트에 붙인 앱스 스크립트 웹 앱 하나입니다
  ([docs/의견받기](의견받기/README.md)). 주소는 `설정 → 💬 의견 받기` 에서 넣습니다.
  - 함께 가는 것은 화면 정보뿐입니다 · **기록의 제목 · 내용 · 사진은 보내지 않습니다**
  - 못 보냈으면 그 기기에 두었다가 다음에 열 때 다시 보냅니다
  - 답을 읽을 수 있으면 읽어 «도착했다» 를 확인하고, 브라우저가 막으면 «확인하지 못했습니다» 라고 그대로 말합니다

### 뺀 것

- **🤖 AI에 건네기** — 단추 · 창 · 머리띠 메뉴 항목을 지웠습니다. 소개·README·사용안내의 해당 절도 함께 지웠습니다.
- **💭 내 생각 / 📚 자료 인용 / 🤖 AI 답변** 갈래는 **그대로 둡니다.** 이건 기록의 출처를 가르는 일이라 AI 기능이 아닙니다.

### 이름

`구글 기록장` · `개인 지식 운영 체계` 를 모두 **`개인지식운영체제`** 로 바꿨습니다.
`index.html` · `view.html` · `intro.html` · `privacy.html` · `manifest.json` ·
`README.md` · `SETUP.md` · `사용안내.md` 44곳. 조사도 함께 손봤습니다 (「…」이 → 「…」가).

## 2026-09-10 (2) · 글자 크기 되돌리기 · 캡처 붙여 보내기

### 화면이 부풀어 보이던 것

글자 배율 기본값이 **1.7배** 였습니다. 본문이 25.5px, 단추 글자가 19.5px, 획 굵기가 600 이라
화면 전체가 굵고 크게 소리쳤습니다. 「글씨 크기나 UI 버튼이 안 자연스럽다」 는 말의 원인입니다.

| 무엇 | 전 | 후 |
|---|---|---|
| 배율 «보통» | 1.5 | **1** (본문 15px) |
| 배율 «크게» | 1.7 (기본값이었음) | 1.2 (본문 18px) |
| 배율 «아주 크게» | 1.92 | 1.42 (본문 21px) |
| 몸글 굵기 | 600 | **400** (큰 쪽을 고르면 450·500 으로 따라 올라감) |
| 제목·단추 굵기 | 800 | 700 |
| 기본값 | 크게 | **보통** |

큰 글씨가 필요하신 분은 `설정 → 모양 → 글자 크기` 에서 그대로 고르실 수 있습니다.
설정 화면의 안내 숫자도 실제와 맞췄습니다 (「약 22px」 → 「본문 15px」).

곁들여 손본 것

- 칩과 작은 단추의 키가 2px 어긋나 한 줄이 들쭉날쭉했습니다 · 안쪽 여백을 맞췄습니다
- 목록 칸 접는 `‹` 의 누를 자리가 21px 밖에 안 됐습니다 · 28×28 로 키웠습니다
- 출처 갈래 셋(내 생각·자료 인용·AI 답변)이 색에 굵기 800 까지 겹쳐 넣기 줄이 소리쳤습니다 · 600 으로

### 캡처를 붙여 보내기

오류는 말보다 그림이 빠릅니다. 💬 창에 캡처 한 장을 붙일 수 있습니다.

- **붙여넣기 `Ctrl+V`** · 끌어다 놓기 · 그림 고르기 세 갈래
- 보내기 전에 긴 쪽 1600px 으로 줄입니다. PNG 로 담고 1.2MB 를 넘으면 JPEG 로 바꿉니다
  (글자가 든 화면이 많아 PNG 를 먼저 봅니다)
- 받은 그림은 **시트가 든 폴더 안** 의 `의견 캡처` 폴더에 들어가고,
  시트의 새 `캡처` 칸에 그 주소가 찍힙니다
- 스크립트는 시트 주인의 계정으로 돌기 때문에, 보내는 사람이 드라이브에 로그인해
  있지 않아도 · 폴더에 아무 권한이 없어도 그림이 들어갑니다
- **공유 설정은 건드리지 않습니다** · 캡처에는 보낸 사람의 화면이 찍혀 있습니다

#### 조용히 버리지 않는다

받는 쪽 스크립트가 옛 판이면 캡처를 그냥 버립니다. 그런데 앱은 「보냈습니다」 라고 말했습니다.
사람은 그림이 간 줄 압니다. 그건 거짓말입니다.
그래서 스크립트가 **캡처를 어디에 담았는지 답으로 돌려주게** 하고,
앱은 그 답을 읽어 「글은 보냈습니다 · 다만 캡처는 저장되지 않았습니다」 라고 그대로 말합니다.
보낸 목록에도 「캡처 빠짐」 이 남습니다.

## 2026-09-10 (3) · 시트 칸을 아홉으로 · 배포가 먹혔는지 확인하는 길

### 칸이 너무 많았다

열일곱 칸이었습니다. 언어 · 기록 수 · 쪽 · 브라우저 원문 · 보낸 기기 · 앱 갱신일이
저마다 한 칸씩 차지하고, 브라우저 원문은 한 칸에 400자가 들어갔습니다.
정작 읽어야 할 「내용」 이 화면 밖으로 밀렸습니다. 표는 읽으라고 만드는 것입니다.

**아홉 칸으로 줄였습니다.**

`접수시각 · 종류 · 내용 · 캡처 · 답 받을 곳 · 상태 · 처리 메모 · 어디서 · 자세히`

앞 일곱이 읽고 처리하는 칸, 뒤 둘이 고칠 자리를 좁히는 칸입니다.
버린 것이 아니라 「자세히」 한 칸에 접어 넣었습니다.

- 브라우저 원문 400자 → `Chrome 148 · Windows` 로 줄여 적습니다
- 「자세히」 칸은 일부러 좁게 세웁니다. 오류를 좇을 때만 넓혀서 읽습니다
- 「보낸 기기」 와 「접수번호」 도 그 안으로 들어갔습니다

### 배포가 먹혔는지 알 길이 없었다

`저장` 만 하고 `배포` 를 안 하면 웹 앱은 옛 코드를 그대로 돌립니다.
그런데 겉으로는 구별할 방법이 없었습니다. 실제로 그 일이 났습니다.

- 스크립트에 **판 번호(`VER`)** 를 두고, 주소를 그냥 열면 `{"ok":true,"ver":3,…}` 이 보입니다
- 앱의 `설정` → `💬 의견 받기` → `시험 삼아 한 통 보내기` 도 받는 쪽 판을 그대로 알려 줍니다
  (「받는 쪽 판 3 (캡처까지 받습니다)」 · 「캡처는 못 받는 판입니다 · 다시 배포하세요」)
- 안내에 `새 배포` 와 `배포 관리` 의 차이를 굵게 적었습니다.
  **`새 배포` 는 주소가 바뀝니다.** 같은 주소를 지키려면 `배포 관리` 입니다

### 시트 메뉴에 하나 더

`의견 받기` → **`시험 줄 지우기`**. 붙이면서 시험 삼아 보낸 줄을 한 번에 치웁니다.
「내용」 이 대괄호로 시작하는 줄만 지웁니다 (`[연결 확인]` · `[캡처 시험]`).
사람이 보낸 진짜 의견은 그렇게 시작하지 않습니다.
