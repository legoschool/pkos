## 2026-09-11 (9) · 홈 두 영역 제거와 기록 저장 수정

홈의 작은 다음 행동과 생각이 머문 날을 제거하고 지식맵·최근 기록을 한 칸으로 배치했다.

현재 화면 기준 기록 생성·수정·새로고침 보존·휴지통 이동·복원 검사를 기록저장.mjs로 남겼다. 모두 통과했다. PC 1440px·휴대폰 390px에서 두 영역 제거와 가로 넘침 없음을 확인했다. 임시 폴더에서 드래그 저장·동명이름 보존·외부 Markdown 자동 반영도 통과했다.

기존 검사 결과: 이름 이관 11/11, 색인 분할 22/22, 화면 탐색 30/34, 자료 가져오기 73/75, 소개 26/27. 화면점검은 이전 편집기 요소를 찾다가 중단했다. 공유·대비 검사는 브라우저 디버깅 연결 실패로 미완료다. 실제 Google 계정 연결은 시험하지 않았다. 전체 기능 통과를 뜻하지 않는다.

## 2026-09-11 (6) · 폴더에 넣은 것을 앱이 읽는다 · PDF·영상 바로 보기 · 링크 미리보기

「폴더에 파일을 넣어 주면 앱에서 불러올 수 있나」 「PPT·PDF 를 안에서 바로 볼 수 있나」 「링크는 미리보기로」 에 답한 판.

### 폴더 다시 읽기 (내 컴퓨터 폴더 방식)

목록 머리의 **「폴더 다시 읽기」** 단추, 그리고 창으로 다시 돌아올 때(1분에 한 번) 조용히 돈다.

| 폴더에 이런 것이 있으면 | 앱은 |
|---|---|
| 색인에 없는 `.md` | 새 기록으로 세운다 · frontmatter 의 `id/type/title/tags/created` 를 읽고, 같은 폴더의 사진은 이름으로 잇는다 |
| 옵시디언·다른 편집기에서 고친 `.md` (파일 시각이 더 새것) | 제목·태그·본문을 다시 읽는다. 앱에서 고쳐 아직 안 쓴 것(`_dirty`)은 덮지 않는다 |
| 어느 글에도 안 걸린 사진·PDF·한글·PPT… | 「자료」 기록 한 편으로 세운다 · 거쳐 온 폴더 이름이 태그. 20개가 넘으면 한 번 묻는다 |
| `.`·`_` 로 시작하는 폴더 · `PKOS-*.json` | 건너뛴다 |
| 폴더에서 지운 파일 | 여기서는 판단하지 않는다 · 목록에 남는다 (후속) |

### 안에서 바로 보기 (폴더 방식)

- **PDF** · 파일 줄 옆 「펼쳐 보기」 → 브라우저의 PDF 보기 틀로 그 자리에서 (`.pdfframe`)
- **영상·소리** · ▶ 누르면 브라우저가 바로 튼다 (드라이브 틀 대신 `<video>`·`<audio>`)
- **사진** · 폴더에서 읽는다 (9/11 (4))
- **한글·PPT·워드** · 브라우저가 그리지 못한다. 줄을 누르면 파일이 새 탭으로 열리며(내려받기) PC 의 프로그램으로 본다. 드라이브 방식에서는 구글 미리보기 틀이 PPT 를 그려 주었다 · 폴더 방식에서 포기한 것 중 하나

### 링크 미리보기

링크 카드에 **제목·설명·대표 그림** 이 붙는다. 브라우저 보안(CORS) 때문에 다른 사이트를 직접 읽을 수 없어서, 공개 미리보기 서비스 **microlink.io** 에 «주소만» 보내 받는다. 기록 내용은 안 보낸다. 받은 것은 이 기기에 남겨(최근 300개) 두 번 묻지 않는다.
`설정 → 고급 → 링크 미리보기` 에서 끌 수 있다. 유튜브는 전처럼 자체 그림. `privacy.html` 에 한 줄 적었다.

### 확인한 것

- 문법 검사 통과 · 가짜 폴더(OPFS)에 `.md`+사진+PDF+PPT 를 넣고 다시 읽기 → 글 1편(사진 연결)·자료 2개 · 그 `.md` 를 밖에서 고친 뒤 다시 읽기 → 제목·태그·본문 갱신 · 콘솔 오류 없음
- **미확인** · 진짜 폴더에서 PDF 펼쳐 보기·영상 재생(가짜 PDF 로는 틀만 확인) · microlink 응답(사설 망에서는 막힐 수 있다 · 막히면 카드는 전처럼 아이콘+주소만)

## 2026-09-11 (4) · 내 컴퓨터 폴더 · 구글 로그인 없이 PC 폴더에 바로 쓴다

드라이브 권한(OAuth)을 주고 쓰는 일이 번거롭다는 말에, **브라우저의 폴더 권한**(File System Access API)으로 PC 폴더에 직접 쓰는 길을 열었다.
그 폴더가 구글 드라이브 데스크톱 안이면 드라이브가 알아서 올린다. 08_사이트 에디터가 쓰던 방식과 같다.
드라이브 API 는 그대로 둔다 · 휴대폰은 그 길로 같은 폴더를 본다.

### 어떻게 쓰나

`설정 → 저장 위치` 맨 위 「내 컴퓨터 폴더 · 구글 로그인 없이」 → **📁 폴더 고르기** → 브라우저가 «이 폴더를 허용할까요» 를 한 번 묻는다.
그다음부터 저장은 그 폴더에 `.md` 와 첨부로 바로 들어간다. 크롬·엣지 PC 에서만 된다.

| 무엇 | 어떻게 |
|---|---|
| 저장 | 「기록마다 폴더 하나」 「한 폴더에 전부」 「자료 분리」 규칙 그대로. 이름 규칙도 그대로 (`mdName` · `entryFolderName`) |
| 파일 ID | `local:폴더/…/이름` · 드라이브 ID 와 접두어로 갈라 둔다 |
| 색인·설정 | `PKOS-index.json` · `PKOS-settings.json` 을 폴더 뿌리에 · 드라이브 방식과 같은 꼴 (조각은 안 나눈다 · 디스크는 크기 걱정이 없다) |
| 휴지통 | `.trash/<기록 폴더>/` 로 **옮긴다** (복사한 뒤 지움 · 브라우저 API 에 옮기기가 없다). 옵시디언의 휴지통 폴더와 같은 이름 |
| 되돌리기 | `.trash/` 에서 제자리로 |
| 완전히 삭제 | 진짜 지운다. 빈 폴더도 치운다. 드라이브 데스크톱은 그 삭제를 드라이브 휴지통으로 올린다(30일) |
| 사진 | `loadDriveImage` 가 `local:` ID 를 보면 폴더에서 읽는다 · 파일 링크는 `local://…` 로 걸리고 누르면 새 탭 |
| 폴더 훑어서 가져오기 | 색인에 없는 `.md` 를 10단계까지 훑어 세운다 · `.`·`_` 로 시작하는 폴더는 건너뜀 · 옆의 사진은 이름으로 잇는다 · frontmatter `id/type/title/tags/created` 를 읽는다 |
| 시작 | 폴더 손잡이를 IndexedDB(`pkos-local`)에 남긴다. 다음에 열 때 권한이 살아 있으면 바로 잇고, 아니면 「폴더 다시 열기」 띠(사람이 눌러야 권한을 다시 받는다 · 브라우저 정책) |
| 드라이브와의 자리 | 폴더가 열려 있으면 드라이브 자동 연결은 쉰다(`driveAutoBoot`). 드라이브 API 의 `syncPending` 은 `local:` ID 기록을 건드리지 않는다 |

### 이 방식에서 안 되는 것

구글 문서 사본 · 링크로 공유 · 웹 쪽으로 공유 · 영상 스트리밍 재생 · 드라이브 고르기 창. 드라이브 ID 가 없어서다. 사용자가 포기하기로 했다(9/11).
휴대폰(드라이브 API)은 PC 가 쓴 기록을 **읽기만** 한다 · 사진은 안 뜬다. `local:` ID 를 이름으로 되찾는 대응은 후속.

### 손댄 곳

`localSyncPending` · `localSaveIndex` · `localSaveSettings` · `localLoad` · `localTrashEntry` · `localRestoreEntry` · `localPurgeEntry` · `localImport` · `localPick` · `localBoot` · `localPermit` (5-9 절).
`syncPending` `saveIndex` `saveSettingsRemote` 첫 줄에서 폴더 쪽으로 갈라진다. `if (connected)` 로만 보던 자리 13곳은 `connected || localOn`.
`slim()` 에 `localDir` 를 더했다. `driveLink()` 가 `local:` 을 안다. 점검용 `window.pkosLocal` 손잡이.

### 확인한 것

- 문법 검사 통과
- 브라우저의 임시 폴더(OPFS)를 가짜 폴더로 붙여 · 저장 → `2026-09-11_경험_…/….md` + 색인 · 휴지통 → `.trash/…` · 되돌리기 → 제자리 · 완전히 삭제 → 파일·빈 폴더 없어짐 · 가져오기 → frontmatter·태그·옆 사진 연결 · 콘솔 오류 없음
- **미확인** · 진짜 폴더 고르기 창(OS 대화상자라 자동 시험 불가) · 권한이 새로고침 뒤에도 남는가 · 사진 첨부 저장 · 구글 드라이브 데스크톱(스트리밍)에서의 속도 · 옵시디언에서 `.trash` 를 같이 쓰는 것

## 2026-09-11 (3) · 왼쪽 탐색과 작업실 배치

PKOS의 왼쪽 탐색, 상단 경로, 작업실 화면을 구성했다.
기능(일정·논문·나침반)은 아직 없다 · 그 자리는 기능이 들어올 때 메뉴에 늘린다.

### 무엇이 생겼나

|---|---|---|

쪽은 둘(`body[data-page]` = `home` · `library`)이고 마지막 쪽은 기기에 남는다(`pkos.page.v1`).

- 칩과 작은 단추의 키가 2px 어긋나 한 줄이 들쭉날쭉했습니다 · 안쪽 여백을 맞췄습니다
- 목록 칸 접는 `‹` 의 누를 자리가 21px 밖에 안 됐습니다 · 28×28 로 키웠습니다
- 출처 갈래 셋(내 생각·자료 인용·AI 답변)이 색에 굵기 800 까지 겹쳐 넣기 줄이 소리쳤습니다 · 600 으로

### 캡처를 붙여 보내기

오류는 말보다 그림이 빠릅니다. 💬 창에 캡처 한 장을 붙일 수 있습니다.

- **붙여넣기 `Ctrl+V`** · 끌어다 놓기 · 그림 고르기 세 갈래
- 보내기 전에 긴 쪽 1600px 으로 줄입니다. PNG 로 담고 1.2MB 를 넘으면 JPEG 로 바꿉니다
  (글자가 든 화면이 많아 PNG 를 먼저 봅니다)
- 받은 그림은 **시트가 든 폴더 안** 의 `의견 캡처` 폴더에 들어가고,
  시트의 새 `캡처` 칸에 그 주소가 찍힙니다
- 스크립트는 시트 주인의 계정으로 돌기 때문에, 보내는 사람이 드라이브에 로그인해
  있지 않아도 · 폴더에 아무 권한이 없어도 그림이 들어갑니다
- **공유 설정은 건드리지 않습니다** · 캡처에는 보낸 사람의 화면이 찍혀 있습니다

#### 조용히 버리지 않는다

받는 쪽 스크립트가 옛 판이면 캡처를 그냥 버립니다. 그런데 앱은 「보냈습니다」 라고 말했습니다.
사람은 그림이 간 줄 압니다. 그건 거짓말입니다.
그래서 스크립트가 **캡처를 어디에 담았는지 답으로 돌려주게** 하고,
앱은 그 답을 읽어 「글은 보냈습니다 · 다만 캡처는 저장되지 않았습니다」 라고 그대로 말합니다.
보낸 목록에도 「캡처 빠짐」 이 남습니다.

- 옛 판 스크립트로 보냈을 때 `shotLost: true` 와 「캡처는 저장되지 않았습니다」 가 뜨는 것 확인

## 2026-09-10 (3) · 시트 칸을 아홉으로 · 배포가 먹혔는지 확인하는 길

### 칸이 너무 많았다

열일곱 칸이었습니다. 언어 · 기록 수 · 쪽 · 브라우저 원문 · 보낸 기기 · 앱 갱신일이
저마다 한 칸씩 차지하고, 브라우저 원문은 한 칸에 400자가 들어갔습니다.
정작 읽어야 할 「내용」 이 화면 밖으로 밀렸습니다. 표는 읽으라고 만드는 것입니다.

**아홉 칸으로 줄였습니다.**

`접수시각 · 종류 · 내용 · 캡처 · 답 받을 곳 · 상태 · 처리 메모 · 어디서 · 자세히`

앞 일곱이 읽고 처리하는 칸, 뒤 둘이 고칠 자리를 좁히는 칸입니다.
버린 것이 아니라 「자세히」 한 칸에 접어 넣었습니다.

- 브라우저 원문 400자 → `Chrome 148 · Windows` 로 줄여 적습니다
- 「자세히」 칸은 일부러 좁게 세웁니다. 오류를 좇을 때만 넓혀서 읽습니다
- 「보낸 기기」 와 「접수번호」 도 그 안으로 들어갔습니다

### 배포가 먹혔는지 알 길이 없었다

`저장` 만 하고 `배포` 를 안 하면 웹 앱은 옛 코드를 그대로 돌립니다.
그런데 겉으로는 구별할 방법이 없었습니다. 실제로 그 일이 났습니다.

- 스크립트에 **판 번호(`VER`)** 를 두고, 주소를 그냥 열면 `{"ok":true,"ver":3,…}` 이 보입니다
- 앱의 `설정` → `💬 의견 받기` → `시험 삼아 한 통 보내기` 도 받는 쪽 판을 그대로 알려 줍니다
  (「받는 쪽 판 3 (캡처까지 받습니다)」 · 「캡처는 못 받는 판입니다 · 다시 배포하세요」)
- 안내에 `새 배포` 와 `배포 관리` 의 차이를 굵게 적었습니다.
  **`새 배포` 는 주소가 바뀝니다.** 같은 주소를 지키려면 `배포 관리` 입니다

### 시트 메뉴에 하나 더

`의견 받기` → **`시험 줄 지우기`**. 붙이면서 시험 삼아 보낸 줄을 한 번에 치웁니다.
「내용」 이 대괄호로 시작하는 줄만 지웁니다 (`[연결 확인]` · `[캡처 시험]`).
사람이 보낸 진짜 의견은 그렇게 시작하지 않습니다.

## 2026-09-10 (4) · 캡처가 안 담기던 진짜 까닭

새 판을 배포하고 캡처를 보냈는데 그림이 안 담겼습니다. 까닭은 **권한** 이었습니다.

앱스 스크립트는 «코드가 무엇을 쓰는지» 를 보고 권한을 받습니다.
캡처를 담는 코드가 없던 판으로 승인해 두었으니, 새 판을 배포해도 드라이브 권한은 없었습니다.
글은 들어가고 그림만 조용히 빠졌습니다.

고친 것

- 시트 메뉴에 **`권한 주기`** 를 붙였습니다. 한 번 실행하면 승인 창이 뜹니다.
  하는 일은 캡처 폴더를 미리 만들어 두는 것뿐이라 여러 번 눌러도 탈이 없습니다
- **실패를 성공으로 세던 것을 고쳤습니다.** `shotOk` 가 «그림이 왔나» 를 보고 있었습니다.
  왔다는 것만으로 참을 주니, 권한이 없어 못 담았을 때도 「캡처까지 갔다」 고 말했습니다.
  이제 «담는 데 성공했나» 를 봅니다
- 예외 원문 300자를 시트 칸에 그대로 넣던 것을 사람 말로 바꿨습니다.
  `⚠️ 캡처 못 담음 · 드라이브 권한 없음 (메뉴 「의견 받기 → 권한 주기」 를 한 번 실행하세요)`
- 앱도 까닭을 뭉뚱그리지 않습니다. «옛 판이라 버렸다» 와 «권한이 없어 못 담았다» 는
  할 일이 다릅니다 · 받는 쪽이 적어 보낸 까닭을 그대로 옮깁니다

### 고친 것 (버그)

| 무엇 | 왜 그랬나 | 어떻게 |

| **옛 이름으로 쓰던 사람의 기록이 안 이어졌다** | 이름을 `pkos.*` 로 바꾸면서, 옛 키를 찾는 자리가 `pkos.` 를 `trace.` 로 바꿔 찾도록 되어 있었다. `^trace\.` 는 `pkos.entries.v2` 에 걸리지 않으니 **한 건도 안 걸렸다.** TRACE·PEER·PKEMS 로 쓰던 사람이 새 판을 열면 기록·설정·쓰다 만 글이 통째로 「없는 것」 이 됐다 | `inheritOldKeys()` 가 `^pkos\.` 를 보고 갈아 끼운다. 점검 열한 가지 다시 통과 |
