# 🗺️ 만든 과정 · 한 장 지도

이 문서는 「어떻게 만들었나」 를 한 장으로 잡은 지도입니다. 자세한 이야기는 각 줄의 문서로 이어집니다.
직접 쓴 글은 [개발배경.md](개발배경.md) 와 [작업기록.md](작업기록.md) 에 그대로 있습니다.

---

## 1. 어떤 방식으로 만들었나

- **만든 사람은 교사 한 명**이고, 코드는 **AI(Claude Code)와 짝을 이뤄** 썼습니다. 사람이 「무엇이 왜 필요한가」 와 「써 보니 어디가 걸리나」 를 말하고, AI 가 코드와 문서를 쓰고, 다시 사람이 실제 계정에서 눌러 보는 되풀이였습니다.
- **문서를 코드와 같은 무게로** 두었습니다. 기능 하나가 생길 때마다 README 와 안내문이 같이 바뀌었고, 결정한 까닭은 코드의 머리 주석과 [작업기록.md](작업기록.md) 에 남겼습니다. 「왜 이렇게 했나」 가 남아 있어야 다음 사람(또는 다음 AI)이 되돌리지 않습니다.
- **자동 점검 도구**를 함께 키웠습니다. 브라우저를 화면 없이 띄워 실제로 눌러 보는 스크립트가 [점검도구/](점검도구/README.md) 에 아홉 개 있습니다. 다만 로그인이 필요한 길은 자동으로 못 들어가서, 그 부분은 늘 사람이 확인했습니다.
- **설계 원칙 다섯**이 처음부터 끝까지 판단 기준이었습니다 · 서버를 두지 않는다 · 내 구글 드라이브에 쌓는다 · 끝은 마크다운 · 파일 하나로 만든다 · 되는 척하지 않는다. ([개발배경.md](개발배경.md) 「설계 결정」)

## 3. 되풀이된 교훈 셋

작업 내내 같은 자리에서 세 번 넘어졌습니다. 이어 고칠 사람이 같은 자리에서 넘어지지 않게 적어 둡니다.

1. **만든 길만 걸어 보면 결함이 안 나옵니다.** 큰 결함은 전부 «만든 뒤» · 고치고·빼고·지우는 자리에서 나왔습니다. 새 기능을 넣었으면 그것을 지우고 되돌리는 길까지 눌러 봐야 합니다.
2. **이름을 바꾸는 일은 화면이 아니라 자료 사고입니다.** 이름은 드라이브 파일과 브라우저 저장 키에 박혀 있어서, 잘못 건드리면 쓰던 사람의 기록이 통째로 «없는 것» 이 됩니다. 그래서 옛 이름을 이어받는 코드가 일부러 남아 있습니다.
3. **사람이 눌러 봐야만 아는 구간이 있습니다.** 자동 점검이 다 통과해도 로그인이 필요한 길에는 한 발도 못 들어갑니다. 배포 뒤에 실제 계정으로 한 번 도는 것을 건너뛰지 않습니다.

## 4. 코드가 어떻게 생겼나 · 큰 그림

`index.html` 한 파일이 위에서부터 번호 붙은 절로 나뉩니다. 절마다 머리 주석에 «왜» 가 있습니다.

| 절 | 무엇 |
|---|---|
| 0 | 소유자 설정 · `OWNER_CLIENT_ID` · `OWNER_API_KEY` (사본을 만들면 여기만 바꾼다) |
| 1~2 | 상수·기본값 · 상태 · 이름 이어받기(`PKOS-index.json` ← 옛 이름) |
| 3~4 | 구글 로그인·드라이브·고르기 창 · 업로드(청크·이어 올리기) |
| 5~7 | 마크다운·HTML·구글 문서로 내보내기 · 색인(조각) · 동기화 |
| 8 | **종이 편집기** · contenteditable 종이와 덩어리(figure) · 저장 직전에 블록 목록으로 되돌림 |
| 9~11 | 사진 넣기·가리기 · 손 메모 · 녹음 · 저장·임시 보관 · 목록·카드·전체 보기·공유 · 의견 보내기 |
| 12~14 | 설정 창 · 이벤트 연결 · 시작 |

저장되는 것은 언제나 **블록 목록**이고, 드라이브에는 마크다운(`.md`)과 구글 문서 사본, 정리된 이름의 첨부 파일로 남습니다.
데이터 흐름은 [README.md](../README.md) 「데이터 흐름」 에 그림으로 있습니다.
