# DOC·XLS·HWP와 ZIP 자동 압축 해제

2026-09-13 작업 기록.

PC 앱: http://127.0.0.1:8788/?localBridge=1

DOC는 Word의 별도 자동화 인스턴스에서 읽기 전용 사본을 열어 PDF로 표시한다. 매크로 자동 실행과 열 때 링크 갱신을 비활성화한다. XLS는 시트를 선택하고 100행씩 넘겨 읽는다. 가로 스크롤로 넓은 표를 본다. 수식은 저장된 계산 결과이며 다시 계산하지 않는다. HWP 5는 본문 구역을 순서대로 읽는다. XLS와 HWP는 프로그램 실행 없이 로컬 라이브러리로 처리한다.

세 형식 모두 본문 검색에 연결했다. 검색과 미리보기가 동시에 요청돼도 변환 순서를 기다린다. 원본의 SHA-256을 함께 확인해 같은 크기·수정 시각으로 바뀐 파일도 이전 미리보기를 사용하지 않는다.

PC 앱 또는 폴더에 새 ZIP을 넣거나 기록에 첨부해 저장하면 ZIP 옆에 같은 이름의 폴더를 만들고 압축을 푼다. 기존 폴더가 있으면 (2), (3)을 붙인다. ZIP 원본은 유지한다. 임시 폴더에 전부 쓴 뒤 새 폴더를 표시하며, 실패하면 임시 결과를 정리한다. 해제된 파일은 기존 폴더 읽기 흐름에서 기록으로 가져온다. ZIP 속 ZIP은 다시 풀지 않는다.

ZIP은 원본 128MB, 압축 해제 합계 512MB, 항목 2,000개까지 처리한다. 상위 폴더 경로, 절대 경로, 링크·특수 파일, Windows 예약 이름, 중복 항목과 암호 ZIP은 거부한다. 자동 해제는 PC 연결 앱에서 제공한다. 브라우저 폴더 연결과 Google Drive API 전용 모드에는 이번 자동 해제를 추가하지 않았다. G:의 Google Drive 동기화 폴더는 PC 연결에서 사용할 수 있다.

제한: HWP 표 안의 글은 읽지만 표 배치·그림·수식·글꼴을 재현하지 않는다. 암호·배포용 HWP와 HWP 3은 지원하지 않는다. XLS 차트·그림·셀 서식은 재현하지 않으며 전체 셀 50만 개를 넘으면 안내한다. 본문·결과 32MB 한도를 적용한다. DOC에는 Word가 필요하다. 공개 웹사이트만으로 PC 프로그램을 실행할 수 없다.

검증: 단위·저장·복구 검사 60개 통과. 격리된 PC 앱 화면 검사 16개 통과. DOC 실제 렌더링, XLS 두 번째 시트와 120행, HWP 예제 본문, 세 형식 검색, ZIP 드롭·압축 해제·원본 보관·해제 파일 검색, 재접속 후 검색을 확인했다. DOC·XLS·HWP·ZIP 원본 바이트가 같았다. 사용자 기록과 블로그 파일은 시험 대상으로 쓰지 않았다.

검증 명령: python -m unittest discover -s local-service -p "test_*.py" 및 python local-service/check_legacy_ui.py. 시험 파일 재생성은 local-service/create_legacy_fixtures.py로 실행한다. 시험용 xlwt는 local-service/runtime/test-vendor에 설치하며, HWP 예제는 설치된 한글 2024의 Present1.hwp를 임시 폴더로 복사한다. 예제 원본은 저장소에 넣지 않는다.

변경 파일: index.html, sw.js, local-service/server.py, presentation_preview.py, preview_word.vbs, legacy_document.py, extract_zip.py. PC 전용 라이브러리 olefile 0.47과 xlrd 2.0.2는 local-service/vendor에 라이선스와 함께 보관한다. PC 실행 폴더와 문서 사본은 공개 배포에서 제외한다.

구현 근거: [Word 읽기 전용 열기](https://learn.microsoft.com/en-us/office/vba/api/word.documents.open), [Word PDF 내보내기](https://learn.microsoft.com/en-us/office/vba/api/word.document.exportasfixedformat), [한컴 HWP 본문 구조](https://tech.hancom.com/python-hwp-parsing-2/), [xlrd API](https://xlrd.readthedocs.io/en/latest/api.html).


## 자동 파일명 줄이기

새 기록 폴더의 기본 이름을 제목으로 변경했다. 새 기록 파일과 자동 이름을 쓰는 첨부는 저장 폴더 이름과 확장자만 사용한다. 기존 설정은 한 번 새 규칙으로 전환하며 기존 저장 파일명과 외부 원본 이름은 유지한다. 동일 이름 처리는 기존 중복 번호 규칙을 사용한다. 앱 스크립트 문법과 폴더 이름 선택 및 원본 이름 유지 조건 5개를 확인했다.


## 첨부 파일 카드와 자동 읽기 알림

편집창과 읽기 화면의 첨부 파일을 이름·형식·열기 메뉴가 있는 카드로 변경했다. PC 연결에서는 기본 앱, 파일 탐색기, 이름 변경, 사본 다운로드를 제공한다. 기본 앱 실행은 문서·미디어 확장자로 한정한다. 자동 폴더 확인의 quiet 옵션을 지키도록 수정했고, Markdown 내부 drive 주석은 글로 표시하지 않는다. 격리 브라우저 검사 4개와 기본 앱 호출 모의 검사, 회귀 검사 60개를 통과했다.

기존 파일 날짜 제거와 기록 통합은 미실행 상태다. 자동 승인 검토가 재귀 이름 변경과 태그·본문·인덱스 수정이 결합된 정리를 거절했다. 개인 작업 폴더에 파일명만 바꾸는 65개 확인안을 남겼다. 실행 전 범위 확인이 필요하다.


## 수정 저장 위치와 사진 로딩

하단 sticky 저장 줄이 본문 미리보기와 겹쳐 정적 배치로 변경했다. 이미지 요청을 파일별로 합치고, 공유 Blob 주소는 화면에서 더 이상 쓰지 않을 때 해제한다. 첨부 메타데이터를 처음 읽을 때 불필요하게 캐시를 지우지 않는다. 읽기 실패는 총 3회 시도하며 이후 클릭 재시도를 안내한다. 사진 캐시·재시도·문법 검사와 격리 브라우저 6개 검사(실제 편집 저장 포함)를 통과했다. 원본 사진 파일을 수정하거나 이동하지 않았다. 저장 경로에 실물이 없는 오래된 사진은 이번 수정만으로 복구되지 않는다.


## 기록 목록 접기 UI

목록을 접을 때 생기던 세로 띠를 없애고 편집창 위에 가로 목록 펼치기 버튼을 배치했다. 접힌 목록의 그리드 칸은 제거하고 접기 버튼에 글자와 접근성 속성을 추가했다. 접기 안내와 지연된 보조 사용 안내를 제거했다. 오류 및 저장 결과 알림은 유지한다. 격리 브라우저 검사 13개를 통과했다. 1920·1280픽셀 접기와 펼치기, 390픽셀에서 펼치기 버튼 접근을 확인했다.


## 도구 모음 겹침과 목록 숫자

스크롤 도구 모음의 투명 배경을 불투명 패널로 변경했다. 휴지통·미정리함 등 상태 메뉴 선택 시 이전 검색·유형·태그·고정 필터를 초기화한다. 유형별 숫자와 전체 숫자는 현재 상태 목록을 기준으로 집계하고, 휴지통 숫자는 목록에서 제외하는 누락 원본 기록을 동일하게 제외한다. 격리 브라우저 검사 16개를 통과했다. 개인 기록과 원본 파일은 변경하지 않았다.


## 목록과 편집·미디어 간소화

기록 목록은 제목을 누르면 아래로 펼쳐지는 방식으로 변경했다. 휴지통 우클릭과 모바일 점 메뉴에서 전체 복원·삭제를 제공하며 삭제는 확인 후 실행한다. 상단의 할 일·목록·번호 목록·인용·코드·역할별 인용·코드 삽입 중복 버튼을 제거했다. 기존 기록의 해당 블록과 Markdown 파서는 유지한다. Markdown 제목·목록·인용·코드 울타리는 저장 시 블록으로 변환한다.

사진 편집의 로컬 파일 읽기를 고치고 사진 클릭으로 모자이크·펜·색상·되돌리기를 제공한다. 새 사진 파일은 입력된 기록 제목과 확장자를 쓰고 중복 번호만 추가한다. 편집 중인 첨부를 별도 기록으로 다시 가져오지 않도록 인식한다. 기존 개인 원본은 일괄 변경하지 않는다.

녹음은 파일만 첨부하며 본문 자동 저장과 전사 안내문 삽입을 제거했다. 새 녹음은 브라우저 디코딩 후 길이가 명시된 WAV로 변환한다. 디코딩을 지원하지 않으면 원본 녹음을 보존한다. 기존 음성도 로컬 및 로그인된 Drive에서 네이티브 재생과 길이 보정을 사용한다. WAV는 압축 녹음보다 용량이 크다.

사진 픽셀 변경, 파일 이름, 음성 첨부, 실제 MediaRecorder 길이 변환, Markdown 저장, 휴지통 복원 및 390·768·1024·1280·1920픽셀을 포함한 새 UI 검사 21개와 기존 UI 검사 16개를 통과했다. 실제 휴대폰 하드웨어·모바일 마이크 권한·실제 Google 로그인 업로드는 이번 격리 검사에 포함하지 않았다.


## 지식 탐색과 웹 수집

앱을 처음 열면 기록창이 열린다. PKOS 제목을 누르면 최근 기록, 연결이 많은 기록, 자주 등장한 단어와 미니 지도가 보인다. 작성 중인 초안은 홈으로 이동하기 전에 임시 보관한다.

관계망과 태그 집계는 휴지통, 로컬 부재, 드라이브 부재 및 연결 폴더 밖 기록을 제외한다. 보관 데이터 자체를 삭제하지 않는다. 본문과 제목, 추출된 첨부 텍스트에서 공통 단어가 2개 이상인 기록을 자동 연결한다. 자동 연결은 수동 관계에 저장하지 않는다. 선을 누르면 근거 단어를 읽는다. 단어 화면은 사용 횟수에 따라 크기를 정하고, 2개 이상 기록에서 함께 등장한 단어를 연결한다. 한국어 형태소 분석이나 의미 임베딩은 적용하지 않았다. 문서별 상위 40단어, 기록 연결 500개, 단어 40개 및 단어 연결 160개로 표시 범위를 제한한다. 80개를 넘는 기록에 쓰인 단어는 기록 간 자동 연결 계산에서 제외한다.

할 일 탐색 메뉴와 삽입 메뉴를 제거했다. 기존 문서의 체크 목록은 보존한다. 캡처 선택창은 이미지 파일, 카메라, 화면 캡처 버튼만 남겼고, 붙여넣기 단축키는 유지한다. 캡처 후 자르기를 기본으로 연다. 웹 브라우저의 화면 공유 대상 선택은 생략하지 않는다. 자동 민감정보 탐지나 자동 모자이크는 구현하지 않았다. 사진 편집에서 직접 영역을 표시한다.

웹 클리퍼는 제목, 선택한 글, 출처 URL을 검토한 뒤 현재 초안에 추가한다. 클리퍼의 '선택한 글 가져오기' 링크를 PC 북마크바에 끌어 놓고, 웹페이지에서 글을 선택한 뒤 실행한다. URL과 텍스트는 PKOS 주소의 fragment로 전달하며 자동 저장하지 않는다. 브라우저 정책에 따라 북마크 실행이 제한될 수 있다. 모바일에서는 글과 주소를 직접 붙여 넣는다. 사이트 바로가기는 이 브라우저의 로컬 저장소에 남으며 기기 간 동기화하지 않는다. http/https 이외 주소는 거부한다.

검증: 임시 기록 폴더와 별도 Edge 프로필에서 기존 편집·미디어 21개와 지식 탐색 18개 점검 통과. 관계망은 390/768/1280 폭, 홈은 390 폭에서도 가로 넘침이 없었다. 실물 휴대폰 카메라와 Google OAuth는 이번에 시험하지 않았다. 공개 배포는 이전 전송 승인 차단이 해제되기 전까지 보류한다.


## 전체 자료 화면과 메뉴 축소

PKOS 제목을 누르면 현재 자료 전체가 이미지와 제목 카드로 열린다. 검색과 최근순, 자동 연결 수 정렬을 제공한다. 시작 화면은 기록창으로 유지한다. 웹 클리퍼와 사이트 바로가기는 왼쪽 폴더 목록 아래에 둔다.

미정리함 탐색 항목, 나중에 정리 체크박스, 유형 만들기 버튼을 화면에서 제거했다. 기존 파일과 기록의 저장 값은 보존했다. 긴 도움말을 전체 자료, 새 기록, 지식맵, 웹 클리퍼, 설정 버튼으로 대체하고 사용자에게 보이는 관계 용어를 정리했다. 캡처와 설정의 부연 설명을 줄였으며 오류 및 저장 상태는 유지한다.

의견 버튼은 파란 배경과 선명한 말풍선 SVG, 의견 보내기 글자로 표시한다. 연락처 입력과 자동 화면 진단 전송을 제거했다. 본문, 유형, 사용자가 첨부한 이미지를 전송하는 기존 기능은 유지한다. 이번 시험에서 실제 의견 전송은 실행하지 않았다.

임시 데이터와 독립 Edge 프로필에서 편집 21개, 지식 탐색 및 화면 23개 점검을 통과했다. 390픽셀 모바일 자료 화면을 이미지로 확인했다. 공개 GitHub 전송은 승인 차단 상태이므로 로컬 수정과 커밋까지만 완료했다.


## 설정과 파일 처리 재점검

로컬 연결 중에도 가져오기 탭이 Google 연결 여부만 검사해 비활성화되던 오류를 수정했다. 로컬 모드에는 폴더 다시 읽기와 파일 가져오기를 제공한다. 파일 가져오기는 현재 편집창의 파일 이름 확인 및 첨부 저장 경로를 사용한다. 가져오기 실패 후 버튼이 다시 활성화되도록 처리했다.

비어 있던 기록 유형 탭에 연수, 아이디어, 자료를 표시했다. 파일 이름 설정은 폴더 이름 또는 글 제목을 고르며 사진은 글 제목을 쓴다. 날짜 토큰은 새 저장 규칙에서 제거하고, 가져오는 문서의 YYYY-MM-DD 접두어는 이름 제안에서 뺀다. 사용자가 이름 확인창에서 수정할 수 있다. 기존 파일은 일괄 변경하지 않는다. 태그가 곧 폴더 문구는 태그별 폴더로, 기본 자리 괄호 표기는 폴더 이름만 보이도록 정리했다.

검증 결과: 파일 저장, ZIP 해제 및 원본 보존, 경로 검증, 이름 변경 복구, 문서 처리, 앱 재실행, 두 브라우저 동시 저장 등 60개 검사 통과. 기존 브라우저 저장 검사 3개는 삭제된 홈 빠른 입력창을 사용해서 실패했으며 현재 새 기록 버튼과 제목 입력칸으로 갱신한 뒤 통과했다. 화면 및 설정 35개 검사도 통과했다. 모양, 저장 위치, 가져오기, 기록 유형, 파일 이름, 의견 받기, 고급 탭을 열었고 로컬 가져오기와 이름 설정 저장 및 재열기를 시험했다.

실행 중인 PC 서비스는 02_구글 기록장을 사용하며 /api/status에서 ready=true를 확인했다. 실제 Google OAuth, 모바일 기기 촬영, Google Drive 동기화 완료 여부, 실제 Office/Hancom 프로그램 실행은 이번에 검증하지 않았다. 자동 정리는 선택한 저장 폴더와 파일명 규칙을 적용하는 범위이며 내용에 따른 자동 폴더 분류는 구현 범위에 포함하지 않는다. GitHub 공개 배포는 전송 승인 대기다.


## 모양 독립 설정과 폴더 다중 선택

색감에 섞여 있던 화면 배치와 글자 크기 규칙을 기본 배치로 분리했다. 글자 크기는 아주 작음, 작음, 보통, 크게, 아주 크게이며 글꼴은 고딕, 명조, 시스템, 굴림, 고정폭에서 선택한다. 글꼴은 기기에 설치된 글꼴과 대체 글꼴을 사용한다. 선택값은 색감을 바꿔도 유지하며 저장하지 않고 닫으면 원래 설정으로 돌아간다. 다크 모드 색감 카드와 캡처 버튼의 흰 배경을 수정하고 경계선 대비를 높였다.

기록 유형 설정은 새 기록의 기본 유형을 선택한다. 작성 중인 초안의 유형은 바꾸지 않는다. 상단 폴더 이름은 자료 목록을 열며 저장 위치 변경은 아래 설정에서 한다. 폴더 목록은 Ctrl/Cmd 토글 선택과 Shift 연속 선택을 지원하고 선택 폴더의 자료를 함께 표시한다. 다중 선택 중 저장 위치는 바꾸지 않는다. 일괄 이동과 삭제 기능은 이번 변경에 포함하지 않는다.

사이트 추가로 버튼 이름을 줄이고 새 사이트에는 제목을 받는다. 기존 YouTube 주소 표시는 YouTube로 바꾸고 제목 수정 버튼을 추가했다. 자동 웹페이지 제목 조회는 하지 않는다. 의견 받기 탭에서 흐릿한 이모지를 제거했다.

임시 폴더와 별도 브라우저 프로필에서 화면 점검 45개 통과. 색감 변경 전후 실제 제목 글자 크기 및 글꼴 일치, 설정 저장/취소, 새 기록 기본 유형, Ctrl 2개 폴더 선택, Shift 3개 폴더 선택, 다크 캡처 색상을 확인했다. 다크 모드 모바일 설정 화면을 이미지로 확인했다.

## 필기 인식과 사진 보기

편집 도구의 더·접기를 제거하고 모든 도구를 표시한다. 손 메모를 필기로 바꾸고 표와 접이식에 전용 선 아이콘을 넣었다. 필기는 기존에 그림 저장만 지원했으나 Tesseract.js 한국어·영어 OCR을 연결해 결과를 수정한 뒤 본문에 넣을 수 있게 했다. 초기 엔진 로딩에는 인터넷이 필요하며 필기 이미지는 브라우저에서 처리한다. 실제 엔진으로 인쇄체 시험 문자열을 인식했으며 손글씨 정확도를 보장하지 않는다.

사진 여러 장은 슬라이드와 바둑판으로 전환한다. 작성 중에는 사진 모아 보기에서 전환하며, 저장된 사진을 누르면 해당 기록의 사진 편집을 연다. 다른 초안을 덮기 전에는 확인한다. 저장 위치 구분자를 콜론으로 바꿨으며 사용자가 작성한 글의 가운데점은 변경하지 않았다.

## 탐색과 저장 위치 표시 통일

목록 접기와 펼치기는 상단의 동일 버튼에서 전환한다. 사이트 추가를 탐색 메뉴 디자인으로 맞추고 자식 없는 폴더 앞 빈 펼침 영역과 선택 강조선을 제거했다. 저장 방식은 왼쪽 아래에 브라우저, 로컬 폴더, 구글 드라이브로 표시하고 상단 중복 표시를 숨겼다. 글 아래의 저장 대상은 저장 폴더로 구분하며 연결 해제 안내는 유지한다.

## 태그 입력 수정과 마무리

쉼표 문자열만 입력하던 칸을 태그 추가·추천·삭제 UI로 바꿨다. Enter, 쉼표, 추가 버튼으로 확정하며 한글 조합 중 Enter는 가로채지 않는다. 쉼표로 붙여넣은 여러 태그와 중복, 앞의 #을 정리한다. 기존 태그를 추천하고 선택하면 해당 태그 하나만 추가한다. 입력 중 태그도 기록 저장과 임시 보관에 포함한다. 임시 자료에서 게임·게이미피케이션 추가, 중복 제거, 삭제 및 저장 후 재열기를 확인했다.

## 필기 지우개와 인식 입력 보정

기본 펜을 굵게로 바꾸고 지우개 크기를 작게, 보통, 크게로 분리했다. 전체 지우기는 필기판 위에 배치했다. 획을 유지한다. 펜 압력의 최소 굵기를 높이고 화면 경계에서 획이 끊기는 처리를 수정했다.

인식용 복사본은 흑백으로 보정하고 빈 여백을 줄인다. 원본은 유지한다. 인식 중 필기를 변경하면 이전 결과를 표시하지 않는다. 브라우저 검사에서 지우개 크기별 삭제 범위, 되돌리기와 전체 지우기를 확인했다. 실제 OCR 엔진의 인쇄체 인식 검사는 통과했으며 손글씨 정확도 향상은 수치로 측정하지 않았다.

## ZIP 첨부 해제와 사진 도구 선택

파일 올리기에서 ZIP 내부 파일을 풀어 첨부로 넣는다. 사진도 표시한다. 기존 ZIP에는 압축 풀어 넣기 버튼을 제공하며 로컬 폴더에 직접 넣은 ZIP도 브라우저에서 해제할 수 있다. 파일 이름은 UTF-8과 한국어 CP949를 읽고 압축 내용의 CRC와 크기를 검사한다. 암호 ZIP과 지원하지 않는 압축 방식은 실패를 표시하고 원본을 유지한다. 현재 파일별 16MB, 전체 48MB 해제 한도를 적용한다. 기록에 넣을 때는 내부 파일을 첨부 목록으로 펼치며 로컬 폴더에 직접 넣을 때는 내부 하위 폴더를 유지한다.

사진 도구는 선택한 버튼을 진하게 표시하고 펜을 선택하면 모자이크 입자 설정을 숨긴다. 펜 색상은 펜에서만 보인다. 펜 커서도 실제 선 굵기에 맞췄다. 브라우저에서 한글 ZIP 해제 내용, 파일 올리기 후 첨부 삽입, 잘못된 경로 거부와 사진 편집을 확인했다.

## 기록별 폴더와 선택 태그

폴더 구성은 기록마다 폴더 생성으로 통일했다. 태그별 폴더 선택은 제거했다. 새 기록과 외부 첨부의 태그 기본값은 빈 목록이며 폴더 이름으로 태그를 자동 생성하지 않는다. 기존 기록의 태그와 실제 저장 위치는 유지한다.

새 파일은 폴더명-태그-파일명 순서로 이름을 만든다. 태그는 선택이다. 태그가 없으면 해당 부분과 중복 구분자를 생략하고 여러 태그가 있으면 첫 태그를 파일 이름에 쓴다. 전체 태그는 기록 메타데이터에 남는다. 첨부는 IndexedDB에 임시 보관한 뒤 기록 저장 시 기록 폴더에 저장한다. 기존 파일 이름은 일괄 변경하지 않는다. 브라우저 검사에서 태그 없는 새 기록, 선택 태그가 포함된 새 기록 파일명, 태그 전체 삭제 후 저장과 설정 유지를 확인했다.

## 새 기록과 버튼 배치 정리

새 기록 옆 폴더 메뉴와 작성창의 폴더 변경 버튼을 제거했다. 저장 위치 변경은 설정으로 모았다. 모바일 더 보기에서도 새 폴더와 기본 자리 항목을 제거하고 저장 폴더 표시는 실제 폴더 이름 또는 브라우저로 통일했다.

상단 단일 버튼 모서리와 높이, 편집 도구 아이콘 크기 및 간격, 창 제목과 닫기 버튼 정렬을 맞췄다. 설정과 사진 편집 제목의 장식 이모지도 제거했다. 모바일 화면을 직접 확인했고 390~1920px 화면 배치, 밝기 변경, 사진 도구 동작 검사를 통과했다.

## 사진 도형과 이모지, 링크 미리보기

폴더 구성 표기를 기록 제목으로 폴더 생성으로 바꿨다. 사진 편집에 네모, 원, 화살표와 이모지를 추가했다. 기본 도형 색상은 빨강이다. 드래그 중 도형을 미리 보며 각 도형과 이모지는 한 번 되돌리기로 제거한다. 이모지 입력칸은 직접 입력과 운영체제 이모지 선택기 입력을 받는다.

링크 블록을 작성할 때 미리보기 카드를 표시하고 일반 본문에 적힌 주소도 별도 미리보기로 표시한다. 본문은 유지한다. 유튜브는 썸네일을 표시하며 일반 사이트는 기존 미리보기 서비스가 제공하는 제목, 설명과 대표 이미지를 사용한다. 메타데이터를 받지 못하면 주소 카드로 남는다. 도형과 이모지의 실제 픽셀 변경 및 되돌리기, 출처 문장 속 유튜브와 사이트 링크 입력의 카드 표시를 브라우저에서 확인했다. 외부 사이트 전체의 메타데이터 응답이나 영상별 재생 허용까지 보장하지 않는다.

## 캡처 편집 통일과 강의 녹화 검토

화면 캡처, 웹캠 촬영과 이미지 선택이 공통 사진 편집기로 연결되도록 수정했다. 펜, 모자이크, 네모, 원, 화살표와 이모지를 같은 창에서 사용한다. 자르기는 영역 선택만 맡고 완료 후 공통 편집기로 돌아온다. 시험용 캔버스 영상 스트림으로 화면 캡처와 웹캠 촬영 진입, 도구 표시, 스트림 해제와 자르기 복귀를 검증했다. 실제 카메라와 화면 공유 권한 선택창은 자동 검사 대상이 아니다.

강의 녹화는 구현 전 검토만 진행했다. 화면과 오른쪽 아래 얼굴을 합성하고 마이크 소리를 함께 저장하는 구조는 브라우저 API로 구현할 수 있다. 전사는 실시간 임시 결과와 녹화 후 음성 재처리로 분리하는 안을 제안한다. 긴 녹화의 파일 분할 저장, 중단 복구, 전사 엔진 선택과 시간별 전사 연결은 아직 구현하지 않았다.


## 강의 화면과 음성을 기록으로 보관

강의 녹화 버튼과 접을 수 있는 녹화창을 추가했다. 화면, 마이크, 선택한 웹캠 얼굴을 합성하며 일시 정지와 재개를 지원한다. 한국어 실시간 전사는 시간과 함께 기록에 붙인다. 녹화 조각을 브라우저에 저장하고 미완료 녹화를 복구한다. 녹화 중 저장한 메모를 찾아 영상을 첨부하고 중복 첨부를 막는다.

검증에는 합성 화면과 음성, 전사 대역을 사용했다. 실제 한국어 인식률과 장시간 수업 안정성을 검증한 것으로 표현하지 않는다. 현재 범위와 남은 확인은 강의녹화_검토.md에 기록했다.
