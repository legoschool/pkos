# DOC·XLS·HWP와 ZIP 자동 압축 해제

2026-09-13 작업 기록.

PC 앱: http://127.0.0.1:8788/?localBridge=1

DOC는 Word의 별도 자동화 인스턴스에서 읽기 전용 사본을 열어 PDF로 표시한다. 매크로 자동 실행과 열 때 링크 갱신을 비활성화한다. XLS는 시트를 선택하고 100행씩 넘겨 읽는다. 가로 스크롤로 넓은 표를 본다. 수식은 저장된 계산 결과이며 다시 계산하지 않는다. HWP 5는 본문 구역을 순서대로 읽는다. XLS와 HWP는 프로그램 실행 없이 로컬 라이브러리로 처리한다.

세 형식 모두 본문 검색에 연결했다. 검색과 미리보기가 동시에 요청돼도 변환 순서를 기다린다. 원본의 SHA-256을 함께 확인해 같은 크기·수정 시각으로 바뀐 파일도 이전 미리보기를 사용하지 않는다.

PC 앱 또는 폴더에 새 ZIP을 넣거나 기록에 첨부해 저장하면 ZIP 옆에 같은 이름의 폴더를 만들고 압축을 푼다. 기존 폴더가 있으면 (2), (3)을 붙인다. ZIP 원본은 유지한다. 임시 폴더에 전부 쓴 뒤 새 폴더를 표시하며, 실패하면 임시 결과를 정리한다. 해제된 파일은 기존 폴더 읽기 흐름에서 기록으로 가져온다. ZIP 속 ZIP은 다시 풀지 않는다.

ZIP은 원본 128MB, 압축 해제 합계 512MB, 항목 2,000개까지 처리한다. 상위 폴더 경로, 절대 경로, 링크·특수 파일, Windows 예약 이름, 중복 항목과 암호 ZIP은 거부한다. 자동 해제는 PC 연결 앱에서 제공한다. 브라우저 폴더 연결과 Google Drive API 전용 모드에는 이번 자동 해제를 추가하지 않았다. G:의 Google Drive 동기화 폴더는 PC 연결에서 사용할 수 있다.

제한: HWP 표 안의 글은 읽지만 표 배치·그림·수식·글꼴을 재현하지 않는다. 암호·배포용 HWP와 HWP 3은 지원하지 않는다. XLS 차트·그림·셀 서식은 재현하지 않으며 전체 셀 50만 개를 넘으면 안내한다. 본문·결과 32MB 한도를 적용한다. DOC에는 Word가 필요하다. 공개 웹사이트만으로 PC 프로그램을 실행할 수 없다.

검증: 단위·저장·복구 검사 60개 통과. 격리된 PC 앱 화면 검사 16개 통과. DOC 실제 렌더링, XLS 두 번째 시트와 120행, HWP 예제 본문, 세 형식 검색, ZIP 드롭·압축 해제·원본 보관·해제 파일 검색, 재접속 후 검색을 확인했다. DOC·XLS·HWP·ZIP 원본 바이트가 같았다. 사용자 기록과 블로그 파일은 시험 대상으로 쓰지 않았다.

검증 명령: python -m unittest discover -s local-service -p "test_*.py" 및 python local-service/check_legacy_ui.py. 시험 파일 재생성은 local-service/create_legacy_fixtures.py로 실행한다. 시험용 xlwt는 local-service/runtime/test-vendor에 설치하며, HWP 예제는 설치된 한글 2024의 Present1.hwp를 임시 폴더로 복사한다. 예제 원본은 저장소에 넣지 않는다.

변경 파일: index.html, sw.js, local-service/server.py, presentation_preview.py, preview_word.vbs, legacy_document.py, extract_zip.py. PC 전용 라이브러리 olefile 0.47과 xlrd 2.0.2는 local-service/vendor에 라이선스와 함께 보관한다. PC 실행 폴더와 문서 사본은 공개 배포에서 제외한다.

구현 근거: [Word 읽기 전용 열기](https://learn.microsoft.com/en-us/office/vba/api/word.documents.open), [Word PDF 내보내기](https://learn.microsoft.com/en-us/office/vba/api/word.document.exportasfixedformat), [한컴 HWP 본문 구조](https://tech.hancom.com/python-hwp-parsing-2/), [xlrd API](https://xlrd.readthedocs.io/en/latest/api.html).


## 자동 파일명 줄이기

새 기록 폴더의 기본 이름을 제목으로 변경했다. 새 기록 파일과 자동 이름을 쓰는 첨부는 저장 폴더 이름과 확장자만 사용한다. 기존 설정은 한 번 새 규칙으로 전환하며 기존 저장 파일명과 외부 원본 이름은 유지한다. 동일 이름 처리는 기존 중복 번호 규칙을 사용한다. 앱 스크립트 문법과 폴더 이름 선택 및 원본 이름 유지 조건 5개를 확인했다.


## 첨부 파일 카드와 자동 읽기 알림

편집창과 읽기 화면의 첨부 파일을 이름·형식·열기 메뉴가 있는 카드로 변경했다. PC 연결에서는 기본 앱, 파일 탐색기, 이름 변경, 사본 다운로드를 제공한다. 기본 앱 실행은 문서·미디어 확장자로 한정한다. 자동 폴더 확인의 quiet 옵션을 지키도록 수정했고, Markdown 내부 drive 주석은 글로 표시하지 않는다. 격리 브라우저 검사 4개와 기본 앱 호출 모의 검사, 회귀 검사 60개를 통과했다.

기존 파일 날짜 제거와 기록 통합은 미실행 상태다. 자동 승인 검토가 재귀 이름 변경과 태그·본문·인덱스 수정이 결합된 정리를 거절했다. 개인 작업 폴더에 파일명만 바꾸는 65개 확인안을 남겼다. 실행 전 범위 확인이 필요하다.


## 수정 저장 위치와 사진 로딩

하단 sticky 저장 줄이 본문 미리보기와 겹쳐 정적 배치로 변경했다. 이미지 요청을 파일별로 합치고, 공유 Blob 주소는 화면에서 더 이상 쓰지 않을 때 해제한다. 첨부 메타데이터를 처음 읽을 때 불필요하게 캐시를 지우지 않는다. 읽기 실패는 총 3회 시도하며 이후 클릭 재시도를 안내한다. 사진 캐시·재시도·문법 검사와 격리 브라우저 6개 검사(실제 편집 저장 포함)를 통과했다. 원본 사진 파일을 수정하거나 이동하지 않았다. 저장 경로에 실물이 없는 오래된 사진은 이번 수정만으로 복구되지 않는다.


## 기록 목록 접기 UI

목록을 접을 때 생기던 세로 띠를 없애고 편집창 위에 가로 목록 펼치기 버튼을 배치했다. 접힌 목록의 그리드 칸은 제거하고 접기 버튼에 글자와 접근성 속성을 추가했다. 접기 안내와 지연된 보조 사용 안내를 제거했다. 오류 및 저장 결과 알림은 유지한다. 격리 브라우저 검사 13개를 통과했다. 1920·1280픽셀 접기와 펼치기, 390픽셀에서 펼치기 버튼 접근을 확인했다.


## 도구 모음 겹침과 목록 숫자

스크롤 도구 모음의 투명 배경을 불투명 패널로 변경했다. 휴지통·미정리함 등 상태 메뉴 선택 시 이전 검색·유형·태그·고정 필터를 초기화한다. 유형별 숫자와 전체 숫자는 현재 상태 목록을 기준으로 집계하고, 휴지통 숫자는 목록에서 제외하는 누락 원본 기록을 동일하게 제외한다. 격리 브라우저 검사 16개를 통과했다. 개인 기록과 원본 파일은 변경하지 않았다.
