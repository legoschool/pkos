이름 변경과 파일 이동·복사, 저장 전 파일명 입력을 구현했다. 실제 폴더 경로와 앱 색인을 함께 갱신하고 파일 내용, 확장자, 이름 충돌, 실패 복구를 확인했다.

화면·스타일 식별자·안내 문서의 참고 표현을 정리했다. 기존 기능 이력은 유지하고 해당 문구만 수정했다. 기본 스타일 키는 plain, 차분한 색감 키는 calm이다. 예전 설정 키는 기본 화면으로 처리한다.

개인 기록 목록 생성기와 읽기 전용 정리 화면, 실행 로그는 공개 커밋에서 제외했다. PDF 엔진의 원본 라이선스·출처 고지는 유지했다. 배포 워크플로는 사이트에 필요한 파일만 묶는다.

최종 검증 결과와 배포 확인은 커밋 후 실행 결과로 별도 기록한다. 사용자의 기록과 블로그 원본은 수정하지 않았다.

## 커밋 전 확인

외부 파일명 화면 검증 7개, 태그·폴더명 화면 검증 7개, 이동·복사 검증 16개를 재실행해 통과했다. 이름 변경 단위 검증은 직전 실행에서 8개 통과했다. 커밋 대상의 참고 표현과 개인 자료·인증키 검사를 수행했다. PDF와 외부 라이브러리는 줄바꿈 변환을 하지 않도록 지정했다.

커밋 파일 전체에서 제거 대상 표현은 발견되지 않았다. 인증키 검사에서 감지된 값은 기존 공개 커밋과 동일한 브라우저 파일 선택기 설정이며 새 키를 추가하지 않았다. 외부 라이선스의 원본 공백은 보존하고 작성 코드의 diff 검사는 통과했다.


## 파일명 입력 키보드 회귀 점검

외부 파일명 입력창에서 Enter 또는 Ctrl+Enter를 누르면 파일명 확인만 완료하도록 했다. 뒤쪽 기록 저장 단축키로 전달되지 않는다. 이름 변경창에서도 Enter·Escape를 해당 창에서 처리한다.

기존 PC 연결·두 창 동시 저장 검사는 파일명 확인 단계를 건너뛰어 실패했다. 실제 입력 순서대로 이름을 확인한 뒤 첨부를 저장하도록 검사 절차를 수정했다. 문서 이름 확인 중 기록이 저장되지 않는 조건을 추가했다. 파일 원본과 첨부 저장 조건은 유지했다.

PC 저장·중단 복구·동시 쓰기·이름 변경을 포함한 Python 회귀 검사 20개가 통과했다. 이 결과를 모든 파일 형식의 미리보기나 모든 외부 서비스 환경의 완전한 검증으로 확대하지 않는다.


## 이름 변경 중 원본 보존 보강

연결 문서와 색인을 직접 덮어쓰는 대신 같은 폴더의 임시 파일에 완성본을 기록하고 flush·fsync 후 교체한다. 교체 직전 원본 내용을 다시 대조하며, 도중에 외부에서 수정됐으면 해당 내용을 덮어쓰지 않는다. 실패 복구 때도 완성본 교체와 내용 대조를 사용한다.

저장 flush 실패, 색인 교체 실패, 임시 저장 도중 외부 수정 주입을 추가했다. 이름 변경 검사 11개가 통과했다. 태그·폴더 이름 화면 검사 7개와 파일명 화면 검사 7개도 재실행해 통과했다. 시험은 격리 폴더에서 수행했다.

이 검사는 호출 실패와 외부 수정 조건을 다룬다. 여러 파일을 변경하는 도중 PC 전원이 끊겼을 때의 전체 작업 복구를 입증한 것은 아니다.

## 마무리 확인 (2026-09-12)

저장·중단 복구·동시 쓰기·이름 변경 검사 23개를 함께 실행해 통과했다. 격리된 시험 폴더를 사용했다. PC 연결 상태도 ready로 확인했다.

기능 커밋 c763c43의 공개 배포가 성공했다. 현재 추적 중인 작성 파일에서 제거 대상 참고 표현이 발견되지 않았다. 과거 커밋 이력은 재작성하지 않았다.

미리보기 범위도 확인했다. PDF는 전용 뷰어를 사용하고 DOCX·XLSX·PPTX·HWPX·ODT·ODS·ODP는 텍스트를 추출한다. 원본 문서의 배치와 글꼴을 그대로 재현하지 않는다. ZIP은 파일 목록을 표시한다. 구형 DOC·XLS·PPT·HWP의 본문 미리보기는 지원하지 않는다. 해당 파일도 저장할 수 있다.

추가 구현은 여기서 멈춘다. 블로그 기록 정리는 사용자에게 남긴다. 다음 작업자는 다중 파일 변경 도중 전원이 끊긴 상황의 복구와 구형 문서 미리보기를 미완료 항목으로 이어받는다.

## 문서 이미지 미리보기 보강

DOCX 본문과 PPTX 슬라이드에 포함된 PNG·JPEG·GIF·WebP 이미지를 텍스트 아래에 표시한다. 이미지가 여러 장이면 이전·다음 버튼으로 넘긴다. 편집창과 전체 보기에서 사용할 수 있다.

문서 내부 이미지 연결만 읽는다. 외부 이미지 주소와 지원하지 않는 형식은 읽지 않으며 본문은 계속 표시한다. 이미지 한 장 4MiB, 문서당 이미지 데이터 8MiB, 표시 항목 48개로 제한한다. 한도를 넘긴 이미지는 생략 안내를 표시한다. 본문 검색에서는 이미지 데이터를 읽지 않는다.

격리 브라우저의 이미지 검사 11개와 기존 문서 미리보기·긴 본문 검색 검사 20개가 통과했다. 시험 문서의 저장 전후 바이트가 일치했고 재실행 후 검색도 확인했다. 사용자 문서를 수정하지 않았다.

원본의 글꼴·배치·도형 효과와 구형 문서 형식은 아직 재현하지 못한다. DOCX 머리글·바닥글 이미지, XLSX·HWPX·OpenDocument 내부 이미지는 이번 범위에 포함하지 않았다.

## 이름 변경 강제 종료 복구

이름 변경 전에 문서와 색인의 변경 전 내용, 변경 후 내용, 경로와 대상 식별값을 비공개 실행 폴더의 복구 기록에 저장한다. 복구 기록을 디스크에 기록한 뒤 실제 파일을 바꾼다. 재시작하거나 다음 쓰기를 처리하기 전에 미완료 작업을 확인한다.

색인까지 저장된 작업은 유지한다. 색인 저장 전에 중단된 작업은 문서와 경로를 원래 상태로 되돌린다. 복구 도중 다시 종료돼도 다음 실행에서 이어서 복구한다. 문서·색인·경로가 외부에서 바뀌었거나 복구 기록이 손상됐으면 원본과 복구 기록을 남기고 추가 쓰기를 차단한다.

복구 기록은 local-service/runtime/rename-<폴더식별값>.json에 저장하며 웹으로 제공하거나 Git에 넣지 않는다. 복구 충돌 시 해당 파일을 지우지 않는다. 인수 담당자가 현재 문서와 기록된 변경 전후 내용을 대조해 외부 수정본을 별도로 보존한 후 경로·내용을 정리해야 한다. 충돌이 해소되면 다음 폴더 점검에서 복구를 다시 시도한다.

별도 프로세스를 저장 단계마다 실제 종료하는 검사, 복구 재중단, 외부 수정 보존과 HTTP 쓰기 차단, 손상된 복구 기록 검사를 추가했다. 기존 저장·동시 쓰기 검사와 합쳐 34개가 통과했다. 태그·폴더 이름 화면 검사 7개도 통과했다. 개인 원본은 시험에 사용하지 않았다.

이 결과는 프로세스 강제 종료 복구를 검증한다. 실제 전원 차단과 저장장치 고장, 이동·복사 전체의 다중 파일 복구까지 입증한 것은 아니다.

## 첨부 파일 단독 이동의 문서 연결 유지

첨부 파일만 옮길 때 앱 색인만 바뀌고 저장된 Markdown 링크는 옛 경로에 남는 문제를 수정했다. 해당 첨부를 사용하는 기록의 링크와 첨부 메타데이터를 새 경로로 갱신한 뒤 색인을 저장한다. 원본 문서를 다시 생성하지 않고 링크 부분만 바꾼다.

상대 경로, 한글·괄호 파일명, 이름 충돌, 설명이 붙은 이미지 링크, 참조형 링크, HTML src·href를 처리한다. 주석과 코드 예시는 유지한다. 이미지 링크의 설명이 파일명에 섞이는 가져오기 오류도 수정했고 물결표 코드 울타리를 인식하도록 했다.

첨부를 사용하는 기록이 편집 중이거나 문서가 외부에서 수정됐으면 이동을 중단한다. 문서를 쓰기 직전에도 내용을 대조한다. 실패하면 원본 첨부를 지우지 않고 완성된 대상 사본을 남긴다. 일부 연결 문서가 이미 수정된 경우에는 남아 있는 대상 사본을 가리킬 수 있다.

연결 이동 검사 12개가 브라우저 저장소와 실제 PC 임시 폴더에서 각각 통과했다. 공유 첨부 문서 두 개, 원본 바이트, 줄바꿈·BOM·주석·코드 보존, 외부 수정 보존과 재연결 경로를 확인했다. 기존 이동·복사 검사 16개도 통과했다.

모든 문서 형식 안의 링크를 일괄 수정하는 기능이나 이동 작업 전체의 강제 종료 복구를 검증한 것은 아니다. 개인 기록과 블로그 원본은 시험에 사용하지 않았다.

## 폴더 이름 변경 시 첨부 파일명 보존

폴더 이름을 바꾸면 하위 첨부의 표시 이름도 폴더 이름으로 바뀌던 오류를 수정했다. 새 첨부 경로에서 실제 파일명을 가져오도록 했다. 파일명을 직접 바꾸는 동작은 기존처럼 새 파일명을 반영한다.

PDF·PPTX·PNG·HWP의 파일명과 확장자, 원본 이름, 바이트를 함께 대조했다. 저장·복구 회귀 검사 35개가 통과했다. 실제 PC 임시 폴더에서 태그와 폴더를 연속 변경한 뒤 앱을 다시 열었으며, 첨부 파일명과 DOCX 본문 미리보기를 포함한 화면 검사 9개가 통과했다.

시험은 새로 만든 파일로 수행했다. 사용자 원본 문서는 변경하지 않았다. 이 결과는 모든 문서 형식의 미리보기나 폴더 밖 문서의 모든 링크 보존까지 입증한 것은 아니다.
